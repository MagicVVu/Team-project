## 接口与字段

家庭库存基础路径：`/api/v1/households/{household_id}/inventory-items`。

| 方法 | 后缀 | 功能 |
| --- | --- | --- |
| GET | 无 | 分页读取当前库存（含数量为零的已用完批次） |
| POST | 无 | 用客户端 UUID 创建独立批次 |
| PATCH | `/{item_id}` | 编辑名称、数量、类别、位置、最低阈值、到期与购买日期 |
| POST | `/{item_id}/adjustments` | 原子增加/消耗库存 |
| DELETE | `/{item_id}` | 从当前库存移除，保留来源与历史 |

创建请求含 `id`、`name`、`quantity`、`unit`、`category`、`storage_location`、`minimum_quantity`、`expires_on`、`purchased_on`。编辑、数量调整和删除请求带 `expected_version`、`operation_id`。调整另带有符号 `delta`。服务端行锁保护并发写入，版本不匹配返回 409；相同操作 ID 与相同内容重试不会重复应用。最近 30 条事件用于历史与重试识别，过旧重试仍被版本号拒绝。创建 UUID 冲突不会创建第二条记录。

购物新增支持可选 `id` 和 `source_inventory_item_id`；来源必须是同一家庭有效库存，并匹配名称、单位。购买请求新增可选 `actual_quantity`，在原购买事务锁内更新数量并创建独立库存，不存在「先改计划、再购买」的竞争窗口。已购买请求重试沿用首次结果，不覆盖数量、购买者及位置。

增加 `PATCH /api/v1/users/me` 保存昵称；`PATCH /api/v1/households/{household_id}` 仅允许 owner/admin 修改家庭名。全部业务接口沿用用户会话与家庭成员鉴权。

迁移仅新增库存最低阈值、JSON 变化记录和购物项的来源库存引用，旧库存默认阈值 0、历史空列表；不自动合并批次或迁移游客数据。

回退服务可恢复此目录的 Compose 配置，再运行：

```bash
cd /srv/magicvvu/magicvvu-starter
cp -a /srv/magicvvu/backups/v08_20261016_045235_zry2Et/compose.yaml deploy/compose.yaml
sudo docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --no-deps --no-build backend
```
