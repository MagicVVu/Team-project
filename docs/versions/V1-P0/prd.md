# V1-P0 PRD：文字库存闭环与手动采购

产品阶段 V1-P0，规格修订 p0-1，2026-10-08。成功标准：用户输入物品变化，经可编辑草稿与明确确认后，库存及事件正确变化；失败、取消和重复请求不会造成额外变化，最近一次变更可以撤销。

## 用户假设与证据边界

主要用户暂定为负责家庭采购与库存整理的人，先处理单用户家庭。待验证的三个问题按优先级为：1. 录入及更新负担；2. 当前数量与位置不清；3. 重复采购。过期浪费、语音便利性和预测价值属于后续假设。

| 假设 | 当前证据 | 后续验证 / 负责人 |
|---|---|---|
| 用户愿意持续记录新增与消耗 | 无真实访谈或行为数据 | Gracie1103 收集过去真实事件、更新频率与放弃原因 |
| 草稿确认可以降低记录错误 | 工程机制与合成测试 | 真实用户任务完成率、改动次数、录入耗时 |
| 库存与位置查询减少重复购买 | 无效果数据 | 对比用户现有清单 / 表格方式，记录实际使用结果 |

这里不是已完成用户研究。访谈对象、原话、时间、替代方案体验与持续记录意愿由调研模块补齐；禁止用 AI 构造表达替代用户证据。替代方案比较维度已确定为录入步骤、更新负担、批次 / 位置支持和纠错方式，未体验的具体产品不作结论。

## 必做与延期

| ID | V1-P0 能力 | 边界 |
|---|---|---|
| REQ-01 | 文字新增 | 单物品、新批次、用户确认；不自动合并同名批次 |
| REQ-02 | 消耗 | 唯一批次、明确数量单位；多批次必须选择 |
| REQ-03 | 库存 / 位置查询 | 来自读工具，逐批次展示不同单位，不跨单位求和 |
| REQ-04 | 草稿编辑 / 取消 / 确认 | 编辑增加修订号；取消不产生库存事件 |
| REQ-05 | 撤销 | 仅当前批次最新非 Correction 事件，带版本校验 |
| REQ-06 | 手动采购清单 | 添加、修改数量单位、删除行、确认；不影响库存 |
| REQ-07 | 失败与手动降级 | 保留文字输入、允许重试或手动草稿，无自动付费重试 |
| REQ-08 | 可靠性与隔离 | 事务、幂等、版本冲突、家庭隔离、Trace |

延期：语音、开封 / 移动 / 丢弃命令、耗尽预测、复杂风险、自动采购建议。图片、扫码、复杂多 Agent、3D、IoT、电商、后台主动通知继续暂缓。标签日期只作为字段展示，不输出药品或食品安全判断。

## 字段与规则

- 新增 / 采购必须有名称、正数量与单位。名称最多 80 字符，数量最多六位小数、上限 10 亿；日期使用 YYYY-MM-DD，未知为 null，位置未知显示“待定位”。购入日期不等于录入时间，未知日期不自动填今天。
- 单位：盒、瓶、包、袋、个、卷、片、ml、L、g、kg；兼容明确的中文别名。仅 ml↔L、g↔kg 可换算，不推断容器容量；其他单位进入澄清或拒绝。新增不同单位的批次不进行自动合并。
- 一次一个物品、一种操作。缺字段、模糊数量、名称不清、零或负数量进入澄清；多物品提示拆分。模型抽取的写字段必须能在输入中找到依据，手动填写不依赖模型。
- 消耗携带 batch_id 与 expected_version，确认时再次校验当前库存、状态、家庭归属与单位。消耗归零只产生一个 Consumed，批次变为 FINISHED。
- 新增 / 消耗的批次与事件写入必须在同一真实数据库事务中。原事件只追加、不删除；事件带 actor、request_id、trace_id、source 和时间。
- 撤销新增使批次变为 REVERSED、数量归零并保留历史；撤销消耗恢复事件前状态，版本继续递增。Correction 引用 original_event_id；未来消费统计应剔除已撤销消费，而非把 Correction 当新消费。
- 草稿修改与库存版本分别校验。重复确认使用同一幂等键及同一请求体，返回原结果；同键不同请求体返回冲突。网络结果不明时重试原提交，不能创建新键重复写入。
- 采购清单仅保存用户明确指定的需求；确认清单不生成库存事件。确认后的清单不可编辑，新采购项开启新清单；不提供自动采购预测或下单。

## 范围变更

新增需求先注明用户证据、验收条件、接口影响及负责人；更新 PRD、原型状态和测试，不能只改某一模块规划。真实调研若否定持续记录意愿，先调整交互负担与核心场景，不提前扩展预测功能。
