# P6 统一验收计划

本文件保留验收标准；当前实现和已执行验证见 delivery-and-validation.md。用户于2026-10-16明确Jev暂缓，后端模块未就绪时先保留接口；正式联合验收另行记录。按 gap-analysis 的 R01—R16 逐项关联证据，不另造一个“测试通过即产品完成”的口径。

## 1. 自动化与契约

保留并通过已有 464 项测试；针对新增行为增加有业务意义的边界测试。旧 P0—P5 工厂和默认契约不能被新配置静默改变；导出 OpenAPI 与实际配置一致。无需为了数量给每个函数添加镜像实现测试。

必测项目：

| 分组 | 正常与边界要求 |
|---|---|
| 生命周期 | 新增/消费/开封/整批移动/部分及全部丢弃、明确用完、多批次、终态、超量、单位冲突、重复开封/原地移动、日期/时区；用完与丢弃分离 |
| 查询 | 当前库存、物找位置、位置找物、待定位、无结果、同名不同单位、完整性/超规模、跨家庭；不混入草稿 |
| 澄清 | 仅允许缺失字段；scope/动作/版本不可被 answers 篡改；过期、修订冲突、候选失效、快照变化重新核对；批次锚点映射必须唯一且事实可信 |
| 恢复 | 原 request_id 幂等、GET 原任务、延迟/重复回调、结果未知、过期及取消；公开不发空 answers/item_key |
| 风险 | 缺规则/事实、相冲突规则、来源核对与人工审核、标签类型、保存条件、已开封、药品和绿色文案；不凭模型延长日期 |
| 统计/预测 | Consumed 净额、Discarded/Finished 排除、逆向关联、重复、迟录、时区、覆盖不足、断货、未来信息、单位/商品映射、陈旧快照；无可靠历史不编日期 |
| 采购 | 阈值/历史依据、已确认未购扣减、购入防双计、偏好缺失、药品排除、整包装依据、planning_basis 保留与确认重校验 |
| 摘要/反馈 | 完整/部分失败、更新时间和来源、读上限、旧版本、提交成功但重算失败；不把 preview 当新事实，不触发自动写 |
| 模型/节点 | 非法 JSON、缺/额外字段、错误类型/动作、非有限数、注入、Jev 不可用和超时；格式拒绝不被统计为正确草稿 |
| 截止时间 | 模型和多次读取共用总截止；首次/续接各不超过 10 秒预算，不自动付费重试；结构化续接与确定性直连接口模型调用为 0 |

AI 运行 Reader 只允许只读操作；通过可观测的调用记录/测试夹具前后状态验证。正式无写与写事务检查仍须真实隔离数据的审计证据。

## 2. 新 V1 综合评测

建议新增独立 240 条文字场景样本：80 个场景组各 3 种表达，48 组/144 条开发、32 组/96 条保留。覆盖全部 V1 意图及缺项、澄清、拒绝、输入口误与恢复；另设确定性专项边界，不用平均分掩盖失败。具体分布在开始开发前冻结并检查每种意图/拒绝分组都有开发和保留覆盖。

每条记录来源、场景组、预期意图/动作、允许字段/状态、澄清需求、事实来源和人工复核状态。AI 构造可用于开发；正式 V1 验收使用人工复核过的预期。冻结后记录数据/代码/提示/规则/模型哈希或版本，保留失败原文及原因。

P5 已暴露的格式失败只能作已知回归/开发案例；旧保留集保留原报告，不能继续把它称作 P6 未见测试。新保留集不用于调提示、阈值或规则；失败后记未通过，修复必须使用新的未见验证，不重跑覆盖旧失败。

门槛：意图准确率 ≥90%，澄清召回率 ≥95%，待确认草稿字段 **100% 正确**，专项边界 **100% 正确**。同时报告有效输入流程完成率、模型格式失败率、各意图结果和完整流程失败数。原阶段采用的严格完整流程检查继续保留，存在未解释的格式/工作流失败时不能宣称严格验收全通过。技术失败安全拒绝是正确防护，但不是成功完成用户任务。

首次文字处理最多一次付费提取，结构化续接 0 次；Jev 单独记录调用/降级。AI+真实只读工具的完整流程 P95 ≤10 秒；样本数、负载、环境、超时率一起报告，不能只统计成功请求。手机 ASR 和端到端耗时分别记录。

按现有凭据与账本机制执行真实模型评测；本次规划不调用付费模型、不改累计预算，也不以费用作为接入阻塞。

## 3. 真实数据、语音和规则

- 风险：纳入发布的规则须具备真实人工审核记录/来源与适用边界；商品专属规则需要包装证据。不用新增未经验证的安全建议凑覆盖。
- 预测：沿用已有回测工具，采集真实时间顺序区间；区分发生/录入时间并剔除未来信息和补货干预，报告可评估覆盖率及误差。误差容忍门槛先按产品用途冻结再看结果，不能事后为通过而调整；数据不足维持试验/条件功能，不称效果达标。
- 语音：承接 P5 建议，至少 30 条获同意的真实表达、至少 3 位说话者及 2 种真实设备/识别环境；不足如实标明范围。记录转写/数量单位/否定词错误、用户修订、任务完成率与耗时，ASR 门槛在真实基线后冻结。保存脱敏文本/审核信息，原音频不默认进 Git 或服务器。
- Jev：用户已明确本轮暂缓，不作为P6验收条件；只验收四节点实际来源与记录，jev_status必须为deferred_by_user，不得伪造模型或置信度。

## 4. 联合端到端验收

由团队提供授权的隔离家庭与真实接口，至少覆盖：

1. 文字新增、转写确认后新增：待确认不写，确认后只生成一次正确批次和事件；重复点击/重连不重复。
2. 多批次消费：选择真实批次、补字段、改草稿、版本变化重核对；只改目标批次。
3. 明确用完：按登记量核对、一次消费至零，Finished 不重复增加消耗；全部丢弃不计消费。
4. 开封、整批移动、部分/全部丢弃：状态和事件正确，重复/原地操作无新变更。
5. 库存/物品位置/位置物品：结果与读取事实、家庭和数量一致。
6. 风险：已审核规则的正常与缺事实分支，页面可追溯规则/版本，未知不保证安全。
7. 真实消费→预测→补货草稿→用户修改→确认清单：依据和最终数量分开保留，已待购/已购不双计。
8. 后端购买入库：只经明确业务确认执行一次；采购草稿确认不会提前入库。
9. 撤销/纠错：明确事件对象、合法性及版本，保留原事件和关联逆向事件，重复/并发不会重复恢复。
10. 故意使事件写失败：库存回滚；相同版本并发操作只有合法结果；跨家庭拒绝。
11. 提交成功后摘要/重算：只用最新已提交事实；计算失败仍显示写入成功，刷新恢复不重复写。
12. 应用重建、任务延迟/失败、取消/重录、过期和旧请求：状态可恢复、原文/已填字段保留，无静默本机写入。

业务写测试必须由对应负责人在授权隔离环境执行；AI 只读检查不能推断事务测试通过。

## 5. 完成报告

最终每一 R/T 项记录：负责人、代码/契约版本、自动测试、模型实测、人工审核、真实读接口、端到端、发布状态及证据链接。没有证据用“未验证/依赖未满足”，禁止用“代码已实现”覆盖全部列。

分别给出 AI 开发完成、AI 验收完成、完整 V1 发布完成三个结论。P6 结束时统一核对剩余项；未完成的 V1 必需项继续计入 V1 欠账，不自动挪进 V1.5。
