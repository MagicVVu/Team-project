# P6 语音与任务承接验收清单

状态：**待前端承接与真机执行**。本轮提供AI输入层、调用方会话参考和任务客户端，不修改Android页面或训练ASR。以下30项为待执行用例，不是已采集的真实语音。

系统ASR→可编辑最终文字→用户确认→正式业务消息→任务GET恢复/非空澄清→读取待确认草稿→独立业务确认。新结果类型使用v1.tasks，输入会话继续复用interaction.session；Python参考实现不代替Android代码。公开消息维持原四字段，内部令牌不得放到手机。

| ID | 待执行场景 | 应有行为 |
|---|---|---|
| V01 | 首次请求录音权限 | 获准才开始录音，不生成业务草稿 |
| V02 | 用户拒绝权限 | 说明原因，提供文字输入 |
| V03 | 永久拒绝权限 | 提供设置入口和文字替代 |
| V04 | 设备无识别服务 | 明确不可用，不静默提交 |
| V05 | 空音频 | 保留编辑入口，不生成草稿 |
| V06 | 无识别结果 | 可重录或手动输入 |
| V07 | 识别超时 | 停止等待，不提交旧文字 |
| V08 | 系统中断录音 | 明确状态，保留可用文字 |
| V09 | 切后台/返回 | 不重复启动或自动提交 |
| V10 | 用户取消录音 | 不产生新AI任务 |
| V11 | 重录 | 新会话替代旧会话 |
| V12 | 旧会话迟到回调 | 忽略，不能覆盖新文字 |
| V13 | 重复识别回调 | 不重复提交 |
| V14 | 修订物品名称 | AI只看到最终名称 |
| V15 | 修订数量99为2 | 不上传原始转写，不按99生成草稿 |
| V16 | 修订单位/日期 | 保留最终字段，冲突明确核对 |
| V17 | 未核对文字直接提交 | 阻止并提示先核对 |
| V18 | 否定/引用/口误 | 重新核对明确请求，不自动生成变更 |
| V19 | 新增/查询分流 | 查询无写入确认表单 |
| V20 | 已用完表达 | 登记量待确认，展示FINISHED预览 |
| V21 | 开封与移动 | 不强制数量，不新建批次 |
| V22 | 部分/全部丢弃 | 区别于消费，数量来源清楚 |
| V23 | 多批次 | 展示真实批次，不默认第一批 |
| V24 | P3商品选择 | 传真实batch_id；统计对应整商品 |
| V25 | 缺字段续接 | 同一任务、修订更新、零模型调用 |
| V26 | 过期/版本冲突 | 读最新候选再核对 |
| V27 | 双击确认文字 | 同一request_id，不新建重复效果 |
| V28 | 网络失败/结果未知 | GET原任务或同键恢复，不静默本机写入 |
| V29 | 应用重建/重新进入 | 保留最终文字、任务和草稿引用 |
| V30 | 业务提交成功但重算失败 | 保留成功，提示刷新，不再次提交 |

联合验收建议至少30条经同意的真实语音、3位说话者及2种设备/识别环境；按P5约定收集基线后冻结ASR门槛。记录设备/识别服务、脱敏文字、数量单位/否定词错误、用户修订、完成率、延迟和审核人。当前上述真实数据均未提供。

风险、预测和采购页面使用[契约字段](ai-contract.md)，明确unknown/数据不足、依据与更新时间。补录事实走业务编辑入口，保存后重新查询；提示不等于已保存。确认和撤销按钮只调用正式业务服务，AI草稿和采购清单确认不自动入库或下单。

正式发布前核实服务版本、旧任务续接兼容、用户/家庭权限、事件审计、幂等和回滚；缺少对应业务模块的按钮应显示未就绪/手动核对，不连接假服务。原音频不默认入Git或上传服务器。
