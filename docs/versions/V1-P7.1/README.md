## 运行与协作

在已核对的 AI 工作区运行以下命令，只检查、不启动：

```bash
cd ~/workspace/agent
.venv-p2/bin/python -B -m integration.runtime_config check --profile p7
```

检查会读取当前进程环境及该目录的私有 `.env.runtime`，私有文件中的非空值覆盖同名进程变量。配置完整性通过不等于网络、内部认证、供应商密钥或账本有效性通过。`BACKEND_BASE_URL` 的主机默认值为本机 8000；容器环境须使用部署负责人确认的实际地址。

部署负责人选择 P7 时的主机启动命令为：

```bash
.venv-p2/bin/python -B -m integration.runtime_config run --profile p7
```

此命令监听 `127.0.0.1:8767` 并占用当前终端。本阶段**未执行启动命令**；已有服务由其原部署方式管理，不应另起重复进程。容器继续使用已有 `Dockerfile.conversation` 和由部署系统注入的环境，主机配置工具不会自动修改容器配置。

服务器同步目标为 `/home/magicvvu_ai/workspace/agent`，按 `conversation/`、`integration/` 等模块存放。只上传 AI 运行文件，说明、测试与评测留在本地仓库；未上传密钥、未删除旧文件、未构建镜像、未改配置、未重启或切换正式服务，未提交或推送 Git。

后端及部署负责人接下来承接：

1. 在实际 AI 部署环境注入原有 `AI_SERVICE_TOKEN`、`BACKEND_TOOL_TOKEN`、正确的 `BACKEND_BASE_URL`，加载已有 DeepSeek 配置，核对所选入口为 P7。当前 SSH 工作区只检查到密钥和模型配置，两项内部令牌尚未注入；这不说明正式容器缺少令牌，也不要求用户重新输入模型密钥。
2. 按现有独立业务执行层契约提供能力声明、版本/幂等校验和真实回执；数据库任务网关保持现有设计。没有正式业务能力的操作继续返回草稿或不可执行状态。
3. 需要跨提问指代时，由受信适配层核实对象引用；公开网关不会因为这次同步自动转发引用。最近聊天文字不能作为最新库存。
4. 在可核实的部署环境完成真实模型与页面联合验收，包含“移动牛奶→选择批次→核对草稿→确认→刷新”以及中断恢复。同步源码和本地测试不能代替此验收。
