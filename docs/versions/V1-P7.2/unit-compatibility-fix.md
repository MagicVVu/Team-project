# V1-P7.2：库存“吨／台”单位冲突修复

日期：2026-10-19（Asia/Shanghai）。**已部署修复，正式全库存查询由 `TOOL_DATA_CONFLICT` 恢复为 `answered`，三条真实记录全部返回。**

## 原因与实际单位

只读检查正式数据库发现，原有库存使用“吨”“台”“个”各一条。前端库存输入接受这些单位；后端内部库存适配器和 AI 单位白名单未包含“吨”“台”，因此转换时返回 HTTP 409，AI 显示 `TOOL_DATA_CONFLICT`。原实现拒绝整批查询，避免跳过不兼容记录后冒充完整库存。

问题属于两侧单位契约遗漏，没有证据表明用户的库存数据错误。本次没有把“吨”改成“kg”，也没有把“台”改成“个”。

## 修改内容

| 文件 | 变更 |
|---|---|
| `agent/p0/domain.py` | 增加“吨”“台”的原样规范化；吨作为质量维度，1 吨=1000 kg=1000000 g；台仅同单位相等 |
| `agent/p0/text.py` | 数量与文字证据解析识别“吨”“台”，草稿字段仍须来自原文 |
| `agent/integration/source_manifest.py` | 将实际修改的共享 `p0/domain.py` 纳入运行同步白名单，白名单由 69 增至 70 文件 |
| `backend/server/app/services/ai_inventory.py` | 只读序列化接受两单位，保留记录的数量、单位、位置和版本 |
| `backend/server/app/services/draft_execution.py` | 确认执行接受两单位，吨与质量单位精确换算；不改变事务、权限、幂等或回执协议 |
| 新增／扩展测试 | 验证同单位、质量换算、计数单位隔离、真实字段一致、消费事件、同键重放、精度拒绝及零写入 |

“台”和“个”、盒、吨之间不能直接转换；吨也不能与升等体积单位转换。换算后超过库存六位小数精度时，AI 要求核对数量，业务确认层拒绝执行；不进行静默舍入。未知单位仍然拒绝，原有“件”等不支持单位的边界测试继续保留。

当前云端聊天页面直接承接结构化草稿，单位输入未使用已弃用的本机演示转换器。本次未修改 Android 页面或本机演示模型，未新增 Mock，未修改数据库任务网关或数据库结构。
