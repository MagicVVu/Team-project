## 5. AI 已支持与业务可执行的差别

| 能力 | AI 侧 | 当前正式后端 / 页面 |
|---|---|---|
| 新增、整批移动、加入采购计划、消耗 | 支持识别、缺字段判断和待确认草稿 | 后端四动作声明可执行；App 有确认及回执处理，本轮未执行真实写入 |
| 开封 | 支持日期解析、重复开封判断和草稿 | `OPEN=false`，不能正式提交 |
| 部分 / 全部丢弃 | 支持数量或全部模式、库存和单位校验、草稿 | `DISCARD=false`，不能以删除库存替代 |
| 消费统计、耗尽预测、AI 补货 | 算法、结构化输出和不足数据处理已实现 | `/internal/v1/planning/context` 未注册，本轮三项接口均返回 `PLANNING_CONTEXT_UNAVAILABLE`，没有伪造零消费或耗尽日期 |
| 查询后继续问“它在哪里” | 内部有限引用和零模型位置表达已部署，重新读取库存 | 公开可信引用适配层未启用；前端也主动拦截部分“它”表达 |
| 当前任务自然补充 | AI `resolve_reply()` 已支持四类续接决策 | 辅助 Kotlin 解析器存在，但当前聊天发送入口仍只硬编码前三个序号；“就第二个吧”“昨天”“两盒”等自由输入尚未统一绑定原任务。候选按钮和补字段表单可用 |
| 风险建议 | 支持依据和不足资料提示 | 实时检查为 partial：`HUMAN_RULE_REVIEW_REQUIRED`、`RISK_FACTS_INCOMPLETE`；人工已审核规则数为 0 |

能力检查只说明 AI 读取与计算能力；是否执行由业务后端的执行能力声明与正式回执决定。算法有代码，不等于已在 App 中可用。

## 8. 推荐推进顺序

1. 前端确认当前目标模拟器/手机，使用本轮成功构建的 `frontend/app/build/outputs/apk/debug/app-debug.apk` 覆盖升级并保留数据；复验登录与家庭选择。安装前仍需核对现有签名；本轮未读取当前设备签名。
2. 后端解决上述合并冲突；前端解决单元测试运行器问题，恢复可重复的发布检查。
3. 三方验收“移动 → 选择批次 → 核对草稿 → 正式提交 → 刷新”，在澄清、提交前和响应丢失时验证恢复及不重复执行。
4. 后端接入受信任的当前任务续接和对象引用；前端统一使用该契约，覆盖自然补充及查询后的指代。
5. 后端补齐开封、丢弃及规划数据；前端承接对应字段、依据、不可用原因及确认反馈。AI 使用已部署接口，不通过通用数量/删除操作冒充业务动作。
6. 前端承接后端已发布的家庭管理功能，按角色显示入口和确认范围。

本次没有升级后端、改数据库、清理环境、扩大公网白名单、更新设备安装包或提交 Git。后续发布应继续分别记录源码同步、服务发布、设备更新和联合验收。
