# P7 后端协作交接

现有数据库网关适合项目，继续使用，不替换、不改源码、不改任务数据库模型。本轮只开发 AI；本文件列出业务负责人后续承接事项。

## 可复用接口与缺口

基于本地后端 0.8.0 源码核对；线上是否已更新需要部署负责人确认。

| 动作 | 已有正式接口 | 确认时要求 / 尚缺内容 |
|---|---|---|
| ADD | POST /api/v1/households/{h}/inventory-items | 用户核对字段、非空位置、稳定创建 UUID；重复同体请求复用原记录 |
| MOVE | PATCH /api/v1/households/{h}/inventory-items/{b} | 只传 storage_location、expected_version、稳定 operation_id；数量保持不变 |
| PLAN_ADD | POST /api/v1/households/{h}/shopping-list/items | 稳定 UUID，匹配来源/单位，自动建议须重验 planning_basis；不买入或下单 |
| CONSUME | adjustments 能调整数量 | 缺少可靠 Consumed 事件与统计读取；不能将泛化数量调整冒充消费语义 |
| OPEN | 数据模型有 opened_at | 公开编辑 DTO 不接开封字段，需独立业务能力；不能宣称已开封 |
| DISCARD | DELETE 可移除记录 | 不等价于定量/全部丢弃事务，需独立语义处理；不能混入消费统计 |

已有路由可复用不代表“AI 草稿确认模块已存在”。库存原子更新、草稿/操作稳定绑定和结果恢复属于业务层。原 AI 网关始终 inventory_written=false，不应为了显示执行状态改写其意义。

## 独立适配与执行责任

- 按当前用户和家庭从数据库核实来源任务及最新修订，只从该结果的真实候选/事实允许建立引用。唯一查询结果可以自动绑定，多个结果需明确选择。不要把手机提交的历史事实直接转成可信引用。
- 为 P7 内部消息添加经过核实的 ObjectReference，绑定原文/request_id/引用不可变。公开四字段网关本身不转发此字段，独立适配层未接时应明确不支持跨提问指代。
- 任务保存、修订 CAS、有效期和并发协调继续由后端负责，AI 不持有最新任务状态。恢复 GET 不执行模型；没有任务 ID 时同键同体恢复。
- 当前网关只接受 needs_clarification 状态的澄清。AI error 返回的已填上下文仍可保存在原任务，但 error 不能直接再次澄清；业务方明确区分恢复查看与重新处理，让用户核对后重建任务或使用手动入口，不改网关状态语义、不自动付费重试。
- 确认层加载当前草稿及原任务依据，验证用户/家庭/动作/字段/版本，锁定目标并执行业务事务。只暴露后端确认过的执行能力，不用 AI 健康接口推断。
- 将草稿修订和规范化操作体绑定到稳定 operation_id/创建 UUID。跨点击、超时、进程重启不能换键重做；修改已确认请求体需要新草稿并重新核对，不能借旧键覆盖内容。
- 后端不接收 AI 预览作为已提交事实；真实提交结果或可信回执才能产生已执行状态。若更新成功但后续刷新失败，仍返回/保留成功。

## 草稿编辑字段

| 动作 | 可编辑业务字段 |
|---|---|
| ADD | 名称、数量、单位、位置、购买/标签日期；位置在正式确认前必填 |
| CONSUME | 数量及兼容单位 |
| OPEN | 合法且不晚于家庭今天的开封日期 |
| MOVE | 目标位置，整批且数量不变 |
| DISCARD | 定量/全部；定量数量和兼容单位，全部由当前库存读取 |
| PLAN_ADD | 数量及兼容单位，重新核对共享待购和原规划依据 |

作用域、action、batch_id、expected_version、来源任务和规划依据不属于普通表单可改字段。改变动作/目标生成新任务。AI 澄清不是草稿编辑通道，不能提交已经不缺失的字段。

目标业务校验仍是权威：当前库存数量六位小数、采购三位小数、位置100字。AI 兼容草稿接受的数量精度/位置长度不自动等于某个业务接口可接受范围；确认层拒绝超限字段并要求用户修订，不能静默舍入或截断。

## 继续沿用的只读契约

规划快照 `/internal/v1/planning/context` 和提交凭证 `/internal/v1/operations/{operation_id}` 沿用 P6，见 ../V1-P6/ai-contract.md。后端缺少对应模块时明确不可用，不拼接展示历史文本伪造事件，不将缺失待购当作零。

供真实消费统计使用的事件必须区分 Consumed、Discarded、Adjusted 和撤销/纠错关联，保持商品映射及完整性。可靠语义事件、迁移和逆向事件由业务组负责，本轮 AI 不直连数据库。
