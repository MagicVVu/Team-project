# P7 实施范围与责任

依据用户确认的家庭库存助手设计，以及“仅 AI 与交接方案”的开发边界。

## 已实施的 AI 工作

1. 新增独立 conversation 配置，P6 和旧版本保留；复用原认证、模型客户端、确定性领域校验和共用预算机制。
2. 15 分钟受信对象引用只绑定身份；数量、单位、位置和版本来自当前工具读取。查询只返回被引用批次，修改还检查读取期间的变化。
3. 明确的新物品名称优先作为新任务处理；指代无引用、已过期、批次结束或不可访问时要求重新核对。
4. 原文与引用分开，模型不接收历史库存事实；引用续接保持原文、目标、版本核对和输入证明。
5. 提供纯调用方解析：当前修订的“第二个”、明确选择的“这一批”、单一日期字段的“昨天”、数量单位补充。歧义转人工字段选择，不调用模型。
6. 提供 P7 公开任务类型、旧任务兼容、健康检查、OpenAPI、构建文件、独立评测和交接说明。

## 确定性逻辑与模型分工

模型只提取原文动作与字段，每次首次处理最多一次。字面明确的指代位置/数量查询、结构化澄清及纯回复解析不调用模型。单位换算、日期转换、数量边界和版本校验使用代码。

后端负责成员权限、最新修订、任务保存、稳定操作 ID、确认事务和真实结果；前端负责候选顺序、表单编辑、展示状态和恢复入口。最低库存差额、明确标签日期的临期计算无需另一次模型请求。

## 保留边界

AI 没有“已执行”状态；状态仍为 answered、needs_clarification、needs_confirmation、unsupported、error。处理和提交状态属于业务任务/界面。用户说“确认”不能代替业务提交凭证。

不开发长期记忆、跨会话偏好学习、多物品多动作联合执行、自动下单、多 Agent、ASR 服务或暂缓的 Jev。不改数据库网关，不把数量调整、删除库存伪装为消费或丢弃事件。

## 发布顺序

AI 本地验证 → 源码同步与服务器导入核验 → 前后端按交接接入 → 隔离测试家庭联合验收 → 部署负责人切换。前两步完成不能标记后续步骤完成。缺少接口的功能显示暂不可用或保留草稿。
