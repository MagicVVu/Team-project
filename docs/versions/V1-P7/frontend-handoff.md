# P7 前端接入交接

本文件是待前端实现的任务，不代表 Android 已修改。当前首页和猫又下拉页复用 MagicApp.kt 的 Chat；CloudStore.ask 仅提取 reply，需改为接收完整任务结果。保留现有视觉设计。

## 页面与字段

| 页面元素 | 数据与行为 |
|---|---|
| 聊天气泡 | 原文、reply、任务关联；历史回答标为当时记录 |
| 批次卡片 | candidates：真实 ID、名称、数量单位、位置、购买/标签/开封日期、状态、版本；不默认选第一批 |
| 补字段表单 | 按 missing_fields / allowed_fields 展示；非空 answers 续接同一 task_id 与 revision |
| 草稿卡片 | draft_id、action、可编辑字段、expected_version、preview.before/after，明确尚未执行 |
| 风险/统计/建议 | 依据、更新时间、unknown/数据不足；未就绪显示原因，不画虚构预测 |
| 补货入口 | 区分“按最低库存补货”和“本次 AI 建议”；不能显示 AI 建议却执行旧阈值算法 |
| 手动处理入口 | 跳到现有详情/采购页；没有相应业务能力时显示暂不可用，不伪造成功 |

OPEN/MOVE 不出现必填数量。DISCARD 区分全部与定量；数量来源注明用户输入/当前库存/规划计算。编辑动作或目标批次时新建任务；普通字段编辑后的确认校验和修订由业务方处理。

确认表单遵循目标业务接口限制：库存数量最多六位小数、采购数量最多三位小数、位置最多100字。AI 通用草稿兼容范围可能更宽，不能因此绕过业务限制；提示用户修订，不能自动四舍五入或截断位置。

## 状态与来源

| 界面状态 | 判定依据 | 可操作项 |
|---|---|---|
| 正在处理 | 任务 processing / 首次请求等待 | 等待、关闭窗口；保留请求 |
| 需要补充 | needs_clarification | 选批次或补允许字段 |
| 待确认 | needs_confirmation | 编辑、确认（能力可用时）、手动入口 |
| 已回答 | answered | 展示只读事实，允许新问题 |
| 提交中 | 独立业务确认请求等待 | 禁止重复点击，保留同一操作 ID |
| 已执行 | 正式业务成功响应或可信回执 | 展示真实结果与刷新状态 |
| 结果待核实 | 提交超时/响应丢失 | 查询原操作或同键恢复，不新建执行 |
| 失败/暂不可用 | 明确拒绝、错误或能力缺失 | 保留原文/表单，核对、刷新或手动处理 |

“用户点确认”“AI 草稿已生成”“AI 回复已完成”都不能变成已执行。已经提交但刷新失败：保留成功状态并提示刷新，不能重新提交。

## 有限上下文与持久化

使用地址＋用户＋家庭隔离当前工作状态，保存原文、最终请求体和 request_id、task_id、revision、draft_id、表单编辑内容、候选修订、明确对象引用及有效期、已确认操作 ID/请求体。凭据沿用现有 Keystore，不存入聊天记录。

窗口状态由页面外生命周期所有者管理。关闭再打开、Activity 重建或应用重启后先读已有 task_id；无 task_id 但已提交的请求仅原体原键恢复。已过期引用不从缓存续期。注销清理该账号活动绑定；切换家庭后旧异步回复不得写入当前对话。

区分“网络结果未知”和“服务器已明确返回 error”。当前网关仅允许 needs_clarification 任务继续补字段；error 任务可以 GET 恢复查看，但不能直接再 POST 澄清。保留本机已填表单和原文，让用户明确核对后重建任务或走手动入口，不自动付费重试，也不宣称旧任务正在继续。

候选顺序与修订一起保存，“第二个”仅解析该修订；请求冲突时获取最新任务重新展示，不能把旧序号套到新列表。无法唯一理解的补充显示字段/批次选择。输入明确新物品或点“开始新任务”后清除旧对象绑定。

Python replies.py 是行为参考，不是已经实现的 Kotlin。手机不直接把 ObjectReference 发给内部 AI；独立业务适配层未提供时，要求用户明确名称或重新选择对象。

## 调用顺序

1. 保存输入与稳定 request_id，再 POST /api/v1/agent/messages。
2. 保存完整任务；需要补充时 POST /api/v1/agent/clarifications/{task_id}，带当前 revision 和非空 answers。
3. 待确认时 GET /api/v1/drafts/{draft_id}，核对归属、版本及待确认状态。
4. 用户确认后调用后端已声明可用的业务操作；缺接口只保留草稿。
5. 根据正式业务结果更新状态并刷新库存/采购；需要 AI 重算时由业务方提供可验证回执。

本阶段没有新增草稿确认公开接口，不能自行调用一个假定的 /drafts/{id}/confirm。
