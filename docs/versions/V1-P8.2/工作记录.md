# V1-P8.2：会话记忆开发工作记录

日期：2026-10-25，Asia/Shanghai。阶段已定义为 V1-P8.2，原有 P8.1 发布记录保持原样。

## 本阶段完成的工作

1. 新增内部认证接口 `POST /agent/conversation-turn`，接受业务后端构建的版本化上下文。旧 AI 消息、澄清和其他服务入口保持兼容。
2. 最近10轮已完成对话与最多20个有来源的任务摘要参与理解。摘要包含任务、动作、缺字段、草稿、已核实执行凭据和资料缺口；不额外调用摘要模型。对象引用与历史正文分开，不把猜测的名称拼进原文。
3. 选批次、补数量和日期、明确对象的数量与位置追问、简短寒暄、任务回顾和明确执行状态解释走确定性路径。其他自然追问最多一次理解，解析结果复用到已有领域流程。
4. 恢复已保存理解时，以内部 `replay` 复用解析、重新读取工具，零模型调用。不会将中断前算出的旧库存结果直接当作当前事实返回。
5. 新增四个公开会话接口，复用 `ConversationTurn` 的 JSON 字段与现有登录游标。会话ID独立于登录ID，每个用户、家庭恢复各自的当前会话。
6. 任务、草稿和聊天轮次通过现有网关的 `on_saved` 回调在同一事务中完成保存。理解结果未知时阻止自动再次调用模型；保存成功但响应丢失时恢复原结果。
7. 查询最新草稿决定和业务回执，解释待补充、待确认、处理中、已执行、已取消、过期、冲突、失败或待核实。加入采购计划只解释为待购，不能描述为购买或入库。
8. 会话恢复、消息和查询结果持续校验用户及家庭权限。对象引用仍为15分钟，不因再次打开窗口或连续聊天延长。候选失效不能移除后把“第二个”改指其他批次。
9. 新会话隔离旧历史和对象，不取消旧草稿；新任务仅清除活动任务引用。旧消息接口不会被隐式并入新会话。

## 数据与兼容边界

- 使用 `binding_json.memory_v1` 保存协议、会话ID、修订、会话边界、活动任务和焦点来源；`resolution_json` 保存理解结果，`response_json` 保存原接受结果。
- 不新增表、迁移、库存写接口或业务执行通道；已有任务网关只增加内部结果提供回调，以保存已经理解的结果。
- 历史读取和输入 AI 限最近30天。没有物理删除原有任务、聊天审计或幂等记录。
- 会话历史可分页；GET 不创建新会话。首次发送前必须初始化会话。
- 上下文最多48,000字节；较早对话先移除并标识截断，必要任务信息过大时明确要求进入原任务处理，不截断候选顺序。模型输入另有原有请求大小保护，进一步裁剪历史时同样标识截断。
- 会话修订、任务修订、草稿修订独立。恢复旧消息时，原响应的修订保留，另返回最新会话修订和最新活动任务。
- P0～P8.1 的契约文件没有被新导出覆盖。兼容测试逐一核对旧 OpenAPI 路径、类型与引用；新解析类型使用独立名称，避免影响旧组件名。

上述10条只验证数量追问，不代表完整意图准确率或整个 App 的端到端 P95。该组已用于问题修复后的回归，不能再当作未来未见样本。样本均待人工复核，完整真实模型意图、澄清召回和正式环境性能验收仍需后续独立评测。
