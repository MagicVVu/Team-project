# V1-P8.4 工作记录

日期：2026-10-27。工作目录为本地仓库；本次不连接服务器进行同步或部署，不执行 Git 提交、推送，不修改 Android、数据库表结构和业务执行事务。

## 本次完成的行为

1. 检查 P8.3、现有会话网关、草稿执行与 Android 入口。旧链路的全局词语过滤、仅允许结构化提取的提示词和逐字字段验证，会把改口、讨论和自然补充误当作不支持。本阶段新增独立协议，旧消息、旧会话理解、原库存写入接口继续保留。
2. 新增 `conversation/dialogue_schemas.py`、`dialogue_engine.py`、`dialogue.py`，提供 understand、resolve、respond 三个内部认证接口。首次理解最多一次模型调用；事实读取、日期/单位/数量计算零模型；自然表达最多一次。明确状态解释、结构化续接和恢复不调用模型。
3. 将请求、讨论、假设、否定、改口、补充、追问、状态及依据分别路由。讨论、假设和否定即使带有模型提议的动作，也不会产生草稿。暂时聊天和其他物品查询保留活动任务。
4. 保留用户原文与独立上下文。字段记录原文片段、当前草稿来源或确定性计算来源。候选按真实顺序和位置定位，不默认第一批；对象引用继续受 15 分钟限制，历史限最近 30 天、最近 10 轮。历史不能作为当前库存或成功回执。
5. “一半”读取最新库存后除以二，“全部余量”读取当前数量；六位小数精度、超量、兼容单位及开封日期继续由确定性规则核对。一口、一点等不估算。多批次半数操作先生成澄清任务，选择后按该批次当前数量计算，零模型续接。
6. 一轮最多四项相关读取和一个草稿。数量、位置、日期共用请求内库存缓存。多修改要求先回答可读信息，再询问优先级；不会执行多条修改。风险、统计、预测及采购建议复用既有计算模块及缺资料提示。
7. 待确认草稿允许同任务改数量、位置或日期。AI 只生成修改结果，后端锁定原任务和草稿、检查最新决定、库存版本、可编辑字段和有效期，再保存修订。动作或对象变化不能覆盖原草稿；已执行、取消、过期或结果未知时先解释状态。全部消耗/丢弃的受保护数量不能变成普通数量编辑。
8. 在现有 `ConversationTurn.binding_json.dialogue_v1` 保存理解计划、已校验结果和表达开始标记。计划保存后中断，原请求恢复仅重新读取并确定性表达；理解结果未知不会自动再次付费。表达失败仍交付已保存的事实与草稿。任务、草稿和回合完成继续使用原网关的原子保存回调。
9. 表达阶段使用已验证事实占位符；缺事实、多事实、重复引用、额外数字/日期/状态或未经核验的自由事实描述均回退到确定性回复，不进行第三次调用。
10. 扩展既有 DeepSeek 传输的可选时间、输入及输出上限；默认值保持原样。继续使用环境变量密钥和既有累计预算账本。未向代码、文档或报告写入密钥，真实模型仅收到合成场景。
