# V1-P8.5 工作记录

2026-10-28。用户要求在 P8.4 上加强会话记忆和自然语言处理，先研究和给出方案，再改进。本轮没有连接服务器，没有修改 Android、后端源码、数据库、Docker 或正式运行配置，没有提交或推送 Git。原有 P8.4 发布记录及工作区修改保留，Jev 不在本轮范围。

## 先分析和规划

检查 P8.4 三阶段流程、上下文、真实模型历史评测和现有会话接口，识别最近十轮之外缺少检索、指代/实时查询/历史回顾容易混淆，以及表达校验过于严格的问题。检索并阅读 LangMem、LangGraph、Mem0、Letta 和 LongMemEval 的项目方文档或仓库，先形成[提升方案](提升方案.md)。仅借鉴设计，未复制开源源码、安装新框架、添加嵌入模型或开通第三方记忆托管。

## 五项实现

| 任务 | 本轮实际实现 |
|---|---|
| 分层记忆 | `conversation/p85/memory.py`：当前任务/实时状态摘要、最近十轮、最多100个已完成片段中按词项和时间选择最多8个；中文双字词项及词频饱和评分；明确最早话题时支持时间方向；返回来源、截断和分页缺口 |
| 话题及对象关联 | 模型只能选择本次提供的 memory_id；对象引用保留原15分钟有效期，重新读取身份/版本；同名多批次不猜第一批；显式新对象与旧话题冲突时重新确认；裸指代优先最近明确对象 |
| 自然语义和续接 | 扩展语义提示和输出契约；序号、数量、开封及移动位置的明确续接零模型；实时库存问法不被回顾路由吞掉；当前任务字段与本轮字段分开；“一半”假设只读计算，实际消耗仍生成待确认草稿 |
| 自然表达 | 日常家庭讨论由一次理解生成自然回复；库存/日期/风险/执行事实仍通过工具及结构化结果；事实表达使用结构化开场/顺序/下一步计划，拒绝缺失或重复事实，失败降级；普通收纳建议不再因“一个抽屉/固定位置”整段误拒；降级时保留用户当前话题 |
| 测试、评测、交接 | 新增独立入口、内部认证、纯历史映射工具、P8.5健康探针、专项测试、240轮新场景、P8.4对照、真实DeepSeek与保存计划回放；导出明确链接的 OpenAPI/Schema |

AI 保持无状态。`archive.py::build_archive` 只是供后端复用的纯映射函数，不读取数据库、不验证手机身份、不保存会话。`memory_delta` 是待业务后端验证保存的记录，不表示已经记住。历史可帮助理解对象，不能供应当前库存数量、位置、变更字段或执行成功凭据。

实现全部位于新增目录 `agent/conversation/p85/`，通过独立工厂 `conversation.p85.app:create_app` 启用。原 `conversation.app:create_app`、P8.4 路由和旧契约保持原行为。新入口仍复用现有数值、单位、日期、只读工具、草稿和预算认证机制。

## 真实评测驱动的修复

开发集首次 143/144 轮、23/24 完整场景通过。首次独立保留组仅85/96轮、8/16场景通过，未达到方案目标，没有覆盖或删除结果。

分析并修复了：模型回传输入字段的格式错误诱因、未标记引用来源的历史名称、混淆任务序号和批次候选、把当前查询判成历史回顾、把“开封记一下”判成新增、把消耗假设误路由到历史统计，以及临时讨论片段抢占最近明确对象。归一化保留本轮原文，重新读目标，来源记录在 `memory.summary.plan_normalizations`。

修复后同组240轮真实回归通过，但已消费的保留组不能重新称为盲测。又用8条独立真实表达检查最终多候选保护，均通过。抽查发现日常建议仍被过度过滤，进一步只调整讨论校验，并使用已保存真实计划回放全部240轮验证，零模型调用，任务结果全部通过；40轮讨论中31轮保留模型自然回答，9轮采用与当前话题相符的备用回复。人工自然度评审仍待完成。
