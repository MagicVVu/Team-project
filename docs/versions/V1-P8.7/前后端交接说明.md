## 2. 新消息与恢复

新消息示例（ID、家庭、修订必须换成真实登录上下文的有效值）：

```http
POST /api/v1/agent/conversation-turns
Authorization: Bearer <existing-login-token>
X-MagicVVu-App-Key: <existing-app-key>
Accept-Language: en
Content-Type: application/json
```

```json
{
  "household_id": "22222222-2222-4222-8222-222222222222",
  "conversation_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "conversation_revision": 0,
  "request_id": "stable-original-request-id",
  "text": "Where is milk?",
  "locale": "en"
}
```

可选任务选择器仍是 `task_id`、`revision`。手机不能提供可信历史、工具结果、批次版本或执行事实。后端把本轮语言保存到现有 `ConversationTurn` JSON 中，再写入内部 `context.locale`。不增加表、迁移或语言数据库。

有效语言在公开消息响应 `locale`、历史每轮 `locale`、内部 run 和重新核对响应 `locale` 中返回。未传 `locale` 的旧请求仍按中文处理，即使 `Accept-Language: en`；读取和错误提示可以使用请求头语言，旧消息本身不能被悄悄改成英文。

读取／恢复／执行示例：

```http
GET /api/v1/agent/conversation?household_id=<home>
Accept-Language: en

GET /api/v1/agent/conversation-turns/<original-request-id>?household_id=<home>
Accept-Language: en
```

切换语言后，新消息用新语言；原请求重放必须保留原请求体、原 `locale`、原 ID。恢复按原 ID 查询，返回原语言回复。历史不翻译；卡片动作、数量单位、状态标签和最新恢复提示按当前界面语言显示。语言设置不能导致模型自动运行。

幂等计算特别保留旧行为：仅在原消息明确传入时才把 `locale` 放入摘要，不把新增默认值加入旧摘要；其他历史默认字段不移除。同 ID 改语言属于改请求，应拒绝，而非重做。恢复成功不能再发一条新 ID 的操作。

## 3. 能力协商及时间

后端 `/api/v1/agent/execution-capabilities` 新增：

```json
{
  "assistant_language_protocol": "assistant-language-1",
  "assistant_languages": ["zh-CN", "en"],
  "inventory_name_resolution_protocol": "inventory-name-resolution-1"
}
```

AI health 同时声明语言协议与支持语言。Android 在发送新英文会话前验证能力；不支持时明确提示并保留输入。旧模式英文请求不会去掉参数后静默发送。实际部署应同时核对 AI 与后端能力，不能只升级后端的声明。

自主循环无固定调用次数上限；仍为 60 秒总预算、最多 58 秒工作、单次模型最多 15 秒、工具读取最多 5 秒。后端 75 秒、租约 120 秒、Android 90 秒读取超时不变。缺数据、需要用户选择、重复计划、错误和待确认草稿都及时结束，不为翻译增加调用。

## 4. 中英规则及跨语言对象

共享规则位于 `agent/p0/language.py`，AI 文案和词表位于 `agent/conversation/language/`；后端和 Android 使用工具生成的词表资产，重新生成命令是 `tools/english_export_contracts.py`。

- 数量：`one`、`twenty-one`、`a bottle` 等；`some`、`a little` 不能猜成固定数量。
- 包装、重量、容量单复数转为现有规范字段；例如 `bottles` → `瓶`、`kilograms` → `kg`。显示可为英文，提交仍是规范字段。
- 日期：`today`、`yesterday`、ISO、`Nov 1, 2026`、`1 November 2026`；以可信时间和家庭时区计算。`11/01/2026` 不猜美式或英式；开封未来日期仍要求修正。
- `the second one`、`number two`、明确数量／单位／日期补充、明确对象位置追问和状态追问可零模型处理。序号必须与本轮文字一致。
- 所有字段仍保留原文引用；规范化记录 `normalization`、`original_value` 或工具事实来源。单位翻译不构成无依据包装换算。
- 当前一条库存是一件实物；英文 `consume half of it` 不能绕过半件限制。`one item` 可据唯一真实物品取得原单位，不能把 `piece` 换算为任意包装数。

跨语言查找复用只读搜索：

```http
GET /internal/v1/inventory/search?name=milk&resolve_names=true
```

可选 `name_variants` 最多三个、每项 1–80 字符，仅为检索提示；不接受 SQL、URL 或代码执行。原名先匹配，英文忽略大小写。原名无结果时用版本化固定词表；模型检索提示命中必须经过用户选择。返回 `data.name_resolution` 的 `query`、`match_kind`、`lexicon_version`，AI 保留匹配批次及版本依据。

| 来源与命中 | 行为 |
| --- | --- |
| 真实原名唯一 | 直接读取或生成待确认草稿 |
| 固定词表唯一 | 保留实际中文名，可继续 |
| 固定词表多条 | 展示实际候选，等待选择 |
| 模型翻译命中，即使一条 | 先询问；确认后续接，零模型处理选择 |
| 无命中 | 说明未找到，请核对名称 |

已有中文位置同样先核对真实位置再使用别名；不唯一必须补充，新位置保留用户输入。确认只在当前任务和原有 15 分钟引用内有效，不形成长期别名学习。任何语言均按用户、家庭鉴权，历史库存事实不能替代重新读取。

## 5. Android 与执行边界

已复用已有 `ui_language` 设置，新增消息加 `locale`，CloudApi 对读取、恢复和执行发送 `Accept-Language`。历史原文不改变。补齐助手处理、错误、候选、草稿、预览、单位、确认、执行反馈和统计／风险卡片的英文系统说明；用户填写的实际名称和位置不翻译。

开封编辑框支持 ISO、`today`、`yesterday`；相对日期在提交时映射为原后端已支持的规范日期词，由后端按可信业务日计算，手机不自行推算日期。新增／到期表单仍按清楚标注的 ISO 格式提交，自然语言日期可在聊天中补充。

确认仍调用现有正式业务接口；AI 永远不写库存和采购。`OPEN`、`DISCARD` 是否可执行仍看现有后端开关，不能因为英文能力声明而打开业务功能。执行成功必须有正式回执；处理中、失败、取消、冲突、待核实都不能解释成成功。风险、预测、补货只改变说明，不改变计算、来源、人审状态或数据不足结论。JEV 路由和审核算法未改。

后端保留错误码，英文提示只说明已知事实；未知错误使用通用提示，保留诊断码，不展示内部堆栈。前端不从回复文字推导执行结果。
