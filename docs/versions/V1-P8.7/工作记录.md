## 已实现

1. 建立共享英文数字、单位、日期、操作语义及序号规则，接入现有确定性证据校验。保留用户原文，规范化有来源记录。英文半件、模糊数量、歧义日期、越权及跳过确认请求仍受约束。
2. 在现有会话 JSON 贯通 `locale`；读取／恢复／执行使用 `Accept-Language` 提示语言。旧请求缺省中文，摘要排除未显式提供的新增默认值。重放继续原语言，不重新请求模型。
3. 扩展原库存只读搜索，支持固定中英词表与最多三个模型检索提示。原名优先、固定映射唯一可继续、模型推测必须选择；移动位置核对真实原名。真实名称、批次 ID、版本及位置不被翻译改写。
4. 依据结构化事实生成英文系统回复、缺字段问题、草稿说明、执行状态和停止原因。自然聊天按语言表达；无额外付费翻译请求。保持自主循环、逐件库存、JEV 和确认执行机制。
5. Android 复用已有语言设置，补齐英文请求头、能力协商、输入保留、任务恢复、候选、预览、编辑、单位、确认及执行卡片。英文编辑单位提交前还原规范值，计算继续用规范值。
6. 新增语言专项测试、150 组中英对照数据、真实 DeepSeek 合成场景评测及离线事实审计。首轮结果保留，礼貌前缀、序号校验及否定修复后另做非盲复测。
7. 在 [contracts/](contracts) 导出 AI／后端 OpenAPI、上下文和消息／恢复 Schema。历史版本契约、模型结果未覆盖。

## 验证中处理的问题

- 英文单位的 `g` 不能从 `fridge` 内部误匹配。
- 已有只读适配器必须保留扩展批次字段，不能在转换时丢失商品或风险资料。
- “Please, the second one” 等礼貌前缀只影响确定性规则匹配，不改模型原文或字段来源。
- 模型选第一项与用户明确第二项冲突时拒绝；不能只检查原文里出现过序号。
- 英文否定不会生成草稿；“已在原位置”和终态物品分别回答，不误报未找到记录或无需移动。
- 后端冲突降级使用本轮语言；读取恢复保留原消息回复，最新状态单独解释。
- 保留既有原始内部动作大写 token 的澄清行为；不把 `DISCARD` 等当普通补字段内容。
- FastAPI 0.116／0.135 的框架校验诊断 Schema 差异仅精确投影可选字段，不放宽业务约束。
- 更新一项旧断言，遵循当前后端“结束实物删除、正式回执保留”的行为；业务清理代码没有修改。

## 未改变的边界

没有新增表、迁移、账本或执行事务；没有修改商品归组、清理规则、JEV 算法或正式数据库任务网关设计。AI 只读并生成待确认结果。其他页面的语言策略沿用现状。

本地测试环境存在旧数量夹具与逐件库存不兼容、旧 SQLite 迁移测试失败，以及 Gradle 测试 worker 类加载问题。具体失败与替代验证在[评测记录](评测记录.md)中公开记录。没有宣称全部后端历史测试、真机或联合验收通过。
