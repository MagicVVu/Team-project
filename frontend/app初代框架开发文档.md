# MagicVVu 移动端前端页面架构与功能说明书

> **文档版本：** V1.0  
> **编写日期：** 2026 年 10 月 13 日  
> **对应原型：** MagicVVu 四栏导航 · 我的页面优化版 V2.1  
> **文档用途：** 团队内部统一移动端页面布局、功能分工、交互流程及页面间关系。  
> **文档范围：** 仅描述用户可见的界面、信息展示与操作行为；不指定开发软件、编程语言、技术框架、第三方服务或具体实现方式。

## 1. 产品定位与设计目标

### 1.1 产品定位

MagicVVu 是面向家庭生活场景的**智能家庭物品库存管理 App**。产品围绕“知道家里有什么、还有多少、放在哪里、什么时候需要补充或处理”展开，帮助用户完成家庭物品的录入、查看、库存检查和采购计划。

AI 管家是 MagicVVu 的特色能力，但并不替代基本的库存管理操作：

- **库存记录**提供物品名称、数量、单位、分类、存放位置、有效期等基础信息。
- **库存状态**根据已有记录提示库存不足、临期或过期等问题。
- **AI 管家**通过自然语言解释库存信息、回答问题并提供建议。
- **快捷添加**通过拍照和语音降低录入门槛。
- **采购清单**承接补货建议，使提醒转化为实际行动。

### 1.2 初版设计原则

1. **打开 App 就能使用 AI。** AI 管家整合到首页上部，不再占据独立底部导航入口。
2. **首页优先呈现高频行为。** AI 提问、拍照添加、语音添加、最近库存状态依次排列。
3. **库存是事实来源。** AI 回复、状态提示和采购建议均应以用户已确认的库存记录为依据。
4. **重要数据变更需要确认。** 识别到物品、理解语音或生成采购建议后，不直接替用户完成库存修改。
5. **导航少而明确。** 仅保留四个一级入口，其他功能放入页面内容区或二级页面。
6. **首版结构稳定、便于扩展。** 未来加入扫码、更多 AI 能力或家庭协作时，原则上不新增底部主导航。

### 1.3 本次确认的核心调整

相较于早期五栏方案，本版采用以下已确认结构：

| 项目 | 最终初版方案 |
| --- | --- |
| 底部导航 | **首页、库存、清单、我的**，共四项 |
| AI 管家 | 放置在**首页上部约三分之一区域**，不单独成为导航页 |
| 首页快捷操作 | **拍照添加、语音添加**，两个并列入口 |
| 首页下方内容 | **最近库存状态**，以需关注物品为优先 |
| 「我的」页面标题 | 固定使用**我的**，不使用“我的家庭”作为页面标题 |
| 「我的家庭」 | 作为「我的」页面的一个**二级功能入口** |
| 个人中心 | 包含账号设置、通用设置、消息通知、隐私与安全等常见入口 |

## 2. 全局页面结构与导航

### 2.1 一级导航

底部导航从左到右固定为：

| 顺序 | 导航名称 | 主要职责 | 典型使用场景 |
| --- | --- | --- | --- |
| 1 | **首页** | AI 管家、快捷录入、库存状态摘要 | 问问题、拍照/语音添加、快速了解库存 |
| 2 | **库存** | 查找与维护所有家庭物品 | 查数量、按类别筛选、查看物品详情 |
| 3 | **清单** | 管理待采购物品与补货任务 | 加入采购计划、确认购买、完成入库 |
| 4 | **我的** | 个人资料、家庭管理及各类设置 | 管理家庭空间、调整提醒规则、账户设置 |

**导航行为约定：**

- 底部四项应始终保持相同顺序、名称和图标含义。
- 当前所在页面使用明确的选中状态；其他入口保持普通状态。
- 点击任意导航项进入对应一级页面，并关闭当前临时弹出的操作面板。
- 普通页面允许上下滚动，底部导航始终清晰可见。
- 拍照、语音识别、详情查看及设置项可使用二级页面或底部弹出面板；需要长时间专注操作的页面允许暂时隐藏底部导航。
- 返回操作应优先回到发起该操作的页面，不能无故清除用户已确认的库存数据。

### 2.2 页面层级概览

```text
MagicVVu
│
├── 首页
│   ├── AI 管家卡片
│   │   ├── 快捷提问
│   │   ├── 文字输入
│   │   └── AI 对话面板
│   ├── 快捷添加
│   │   ├── 拍照添加 → 识别结果确认 → 添加成功
│   │   └── 语音添加 → 语音解析结果确认 → 添加成功
│   ├── 最近库存状态
│   │   └── 物品详情
│   └── 库存提醒
│       └── 异常物品详情
│
├── 库存
│   ├── 搜索物品
│   ├── 分类与状态筛选
│   ├── 库存统计
│   ├── 物品列表
│   │   └── 物品详情
│   └── 添加入口（初版可复用语音添加）
│
├── 清单
│   ├── 待采购清单
│   ├── 根据库存推荐
│   └── 购买确认 / 入库确认
│
└── 我的
    ├── 个人资料卡片
    ├── 家庭与物品管理
    │   ├── 我的家庭
    │   └── 库存检测规则
    ├── 账号与个人设置
    │   ├── 账号设置
    │   ├── 通用设置
    │   ├── 消息通知
    │   └── 隐私与安全
    └── 支持与关于
        ├── 帮助与反馈
        └── 关于 MagicVVu
```

### 2.3 全局顶部区域

页面顶部采用统一的标题区域，按当前页面显示名称。

- **首页：** 以“你好，欢迎回家”作为欢迎语，可辅以 MagicVVu 产品标识或简短副标题。
- **库存：** 显示“我的库存”。
- **清单：** 显示“采购清单”。
- **我的：** 显示“我的”。
- **提醒入口：** 首页及适当的主页面右上角可展示消息/提醒图标；点击打开库存提醒列表。
- **个人入口：** 右上角头像或个人图标点击后进入「我的」，与底部「我的」导航指向同一页面。

提醒存在未处理事项时，可使用角标提示；角标表示待处理提醒数量，不应与库存物品总数混淆。

## 3. 首页：AI 管家与高频操作中心

### 3.1 首页定位

首页是 App 的核心使用入口，用户应能在不进入其他一级页面的情况下完成以下行为：

1. 向 AI 管家询问库存问题。
2. 通过拍照或语音发起物品添加。
3. 查看最近需要关注的库存状态。
4. 打开某件物品的详情，或进入完整库存列表。

首页应避免重复展示大量完整库存条目，也不应把所有设置、分类与采购功能直接堆叠到首屏。

### 3.2 首页从上到下的区域顺序

```text
┌──────────────────────────────┐
│ 顶部：欢迎语       提醒  头像 │
├──────────────────────────────┤
│                              │
│        AI 智能管家区域        │
│  库存摘要 / AI 形象           │
│  常见问题快捷按钮             │
│  输入框与发送按钮             │
│                              │
├──────────────────────────────┤
│ 快捷添加                     │
│ [ 拍照添加 ]  [ 语音添加 ]     │
├──────────────────────────────┤
│ 最近库存状态       查看全部 > │
│ 需关注物品 1                 │
│ 需关注物品 2                 │
│ 其他最近物品……               │
├──────────────────────────────┤
│ 首页    库存    清单    我的   │
└──────────────────────────────┘
```

**布局要求：** AI 管家为首页第一主视觉区，建议占手机首屏可用内容高度约三分之一，具体高度随不同屏幕与内容适当调整；快捷添加紧随其后；最近库存状态排在下方，允许通过滚动继续查看。底部导航始终固定。

### 3.3 AI 管家区域

**展示内容：**

| 子区域 | 展示内容 | 用户操作 |
| --- | --- | --- |
| 卡片标题 | “AI 智能管家”、简短陪伴式文案 | 识别当前功能 |
| AI 形象 | 机器人、管家形象或简洁标识 | 视觉辅助，不承担必要操作 |
| 库存摘要 | 如“有 2 类物品库存不足，1 类物品即将过期” | 快速了解家庭状态 |
| 快捷提问 | “哪些快过期了？”、“需要补什么？”等 | 点击直接发起提问 |
| 更多提问 | “更多提问”等扩展入口 | 打开完整对话面板 |
| 输入区域 | 用户自行输入问题，点击发送 | 发起自然语言查询 |

**交互说明：**

- 点击快捷问题相当于发送对应问题，进入 AI 对话视图查看回复。
- 在首页输入框输入内容并发送后，保留输入内容在当前会话中，展示“用户问题 + AI 回复”。
- 对话视图应能区分用户消息和 AI 消息，支持持续追问，并可以关闭后返回首页。
- AI 回答优先呈现与库存相关的事实，再提供建议，例如当前数量、最低库存、过期时间等。
- AI 建议执行实际动作时，应提供独立操作入口，例如“加入采购清单”，由用户确认后生效。
- AI 无法确定物品、数量或用户意图时，应明确说明不确定性，不擅自填入库存数据。
- AI 卡片不会把整个首页变成聊天记录页；长对话放在独立对话面板中查看。

**重要边界：** AI 管家可以解释和建议，但不应在未经用户确认时直接增加、减少或删除库存，也不应未经确认生成真实采购记录。

### 3.4 快捷添加区域

本区域固定展示**两个并列快捷入口**，而不是单一的“添加”按钮：

| 入口 | 标题 | 简短说明 | 点击后 |
| --- | --- | --- | --- |
| 左侧 | **拍照添加** | 拍一下，快速识别 | 进入拍照/选图及物品确认流程 |
| 右侧 | **语音添加** | 说出来，轻松记录 | 进入语音输入及识别结果确认流程 |

每个快捷入口应同时具有易辨识的图标、标题和说明文字；整个卡片可点击，避免点击范围过小。

### 3.5 最近库存状态区域

本区域主要回答“最近有哪些物品需要我关注”。

**顶部：** 左侧为“最近库存状态”，右侧为“查看全部”，点击进入「库存」页面。

**列表条目应包含：**

- 物品缩略图或类别图标。
- 物品名称。
- 当前库存数量及单位。
- 存放位置。
- 库存状态标签，例如“库存不足”“临期提醒”“已过期”“状态正常”。
- 整行可点击，进入对应物品详情。

**展示原则：**

- 优先展示需要关注的物品，再展示正常物品。
- 首页只显示少量条目（建议约 3—4 条），完整数据由「库存」页面承载。
- 库存数据变化后，状态和数量应随之刷新。
- 当没有物品记录时，显示“还没有记录物品”，并引导使用拍照或语音添加。
- 当存在库存但没有异常时，显示积极且明确的正常状态，不应人为制造提醒。

### 3.6 顶部库存提醒

点击提醒图标后，打开库存提醒列表。

- 提醒类型包含：库存不足、即将过期、已过期。
- 每条提醒应说明对应物品及原因，例如“牛奶剩余 1 盒，低于最低库存 3 盒”。
- 点击提醒进入对应物品详情。
- 如无提醒，展示“当前没有需要处理的物品”。
- 提醒属于库存状态的集中呈现，不单独成为第五个底部导航。

## 4. 拍照添加：页面与确认流程

### 4.1 功能目标

减少逐字输入负担，使用照片辅助用户录入家庭物品。此流程的核心不是“自动入库”，而是**拍照识别后由用户核对并确认**。

### 4.2 页面流程

```text
首页 → 点击「拍照添加」
     → 拍摄照片 / 选择已有照片
     → 查看识别候选物品
     → 确认或修改物品信息
     → 点击「确认添加」
     → 成功反馈 → 返回首页或查看库存
```

### 4.3 识别结果确认页

| 信息 | 页面要求 |
| --- | --- |
| 图片预览 | 可查看本次选中的照片 |
| 识别物品名称 | 允许用户修改识别错误的名称 |
| 物品数量 | 由用户输入或确认，不将照片中可见数量直接视为实际库存 |
| 单位 | 例如个、盒、袋、瓶、包，可按物品性质选择 |
| 类别 | 可选择食品、日用品等现有类别 |
| 存放位置 | 可选择冰箱、厨房、储物柜等已有位置 |
| 有效期 | 如果适用，允许输入；不适用时可以留空 |
| 确认按钮 | 用户完成核对后才正式加入库存 |
| 取消/重新拍摄 | 允许放弃本次结果，不改变库存 |

实际页面可以将“名称、数量”作为最醒目的必填内容，将其他字段折叠或放在后续补充区域，避免录入流程过长。

### 4.4 异常与重复项处理

- 识别失败：提示无法识别，提供重新拍摄、改选照片或手动填写名称的方式。
- 识别出多个候选物品：由用户选择正确目标或分别确认需要录入的物品。
- 已有同名物品：提示“该物品已在库存中”，让用户选择新增入库、更新盘点结果或取消；不能无提示重复累加。
- 数量无效：提示输入正确的正数，不能提交空值或负数。
- 用户取消：不创建库存变更。
- 添加成功：展示成功提示；首页库存状态与库存列表同步反映变化。

> **原型与正式产品的差别：** V2.1 HTML 中的拍照识别是模拟展示，默认演示识别“苹果”。正式开发时应保留上述确认步骤，而不是沿用模拟数据的固定结果。

## 5. 语音添加：页面与确认流程

### 5.1 功能目标

用户通过自然语言快速表达添加意图，例如“添加两盒纯牛奶”“厨房里放了三袋面包”。

### 5.2 页面流程

```text
首页 → 点击「语音添加」
     → 说出需要录入的物品
     → 展示识别文字
     → 提取名称、数量、单位等信息
     → 用户检查并编辑
     → 确认添加 → 成功反馈
```

### 5.3 语音添加页面组成

1. **语音输入区：** 明确提示用户正在等待输入、正在输入或输入结束。
2. **识别文字区：** 展示用户说出的内容，避免只显示处理后的结果。
3. **信息确认区：** 至少包含物品名称、数量和单位；可补充类别、位置、有效期。
4. **操作区：** 包含重新输入、手动修改、确认添加和取消。

### 5.4 特殊情况

- 当语音不清楚时，显示未识别成功并允许重试。
- 当识别文本含有多个物品时，用户应能逐项核对，而不是只保存第一个物品。
- 当用户只说“添加牛奶”而未说明数量时，必须要求补充数量。
- 当单位不明确时，展示可选择的单位，不应无提示地使用错误单位。
- 当识别结果与已有库存物品重名时，采用与拍照添加一致的重复项确认规则。
- 用户未确认前，不更改正式库存记录。

> **原型说明：** V2.1 使用“添加 2 盒纯牛奶”作为模拟识别文本。它是交互示例，不代表真实录音与识别已经完成。

## 6. 库存页：物品查询与库存管理

### 6.1 页面定位

「库存」是所有家庭物品记录的集中管理入口，负责**查看、搜索、筛选、追踪和修改库存**。首页展示的是摘要；库存页展示的是可操作的完整物品列表。

### 6.2 页面结构

从上到下建议为：

1. 页面标题“我的库存”和简短说明。
2. 搜索框。
3. 分类或状态筛选按钮。
4. 库存统计区。
5. 库存物品列表。
6. 添加物品入口（首版可复用语音添加，也可在后续补充其他录入方式）。

### 6.3 搜索与筛选

**搜索框：**

- 支持按物品名称查找。
- 输入后列表显示匹配的物品。
- 搜索结果为空时显示明确的空状态。
- 清空搜索内容后恢复当前筛选条件下的完整列表。

**初版固定筛选：**

| 标签 | 展示范围 |
| --- | --- |
| 全部 | 所有已记录物品 |
| 需关注 | 存在低库存、临期或过期问题的物品 |
| 食品 | 类别为食品的物品 |
| 日用品 | 类别为日用品的物品 |

当前筛选按钮需有明显选中状态。搜索与筛选应能配合使用，不能互相覆盖用户意图。

### 6.4 库存统计区

初版显示以下三个统计值：

- **物品种类：** 当前家庭记录的不同物品条目数量。
- **库存不足：** 当前数量低于最低库存阈值的物品条目数量。
- **即将过期：** 已记录有效期、且在提醒时间范围内尚未过期的物品条目数量。

统计值应跟随物品添加和库存变更同步刷新。不同统计指标可以重叠，例如某件物品同时可能库存不足且临期，不能强行保证统计数字相加等于物品总数。

### 6.5 物品列表

每一条物品展示：

| 内容 | 说明 |
| --- | --- |
| 图标/缩略图 | 辅助辨认物品 |
| 物品名称 | 例如纯牛奶、鸡蛋、草莓酸奶 |
| 数量与单位 | 例如 1 盒、2 个、3 杯 |
| 存放位置 | 例如冰箱、厨房、储物柜 |
| 状态标签 | 库存不足、临期提醒、已过期、状态正常 |
| 点击反馈 | 进入该物品的详情视图 |

当一件物品同时存在多种异常时，可突出最紧急的一项，并在详情中呈现其余异常原因。不要因为只显示一个标签就遗漏其他问题。

### 6.6 物品详情页

物品详情页是库存操作的二级页面，至少需要能够查看：

- 物品名称和图片（如有）。
- 当前数量与单位。
- 所属类别。
- 存放位置。
- 最低库存阈值。
- 有效期（如适用）。
- 当前库存状态及触发原因。
- “加入采购清单”入口（当存在补货需求时）。

**正式初版建议完善的操作：**

- 编辑物品基本信息。
- 增加库存数量（入库）。
- 减少库存数量（消耗/出库）。
- 查看最近的数量变化记录。
- 删除物品时二次确认。

上述操作属于完整库存管理闭环所需的细化交互；V2.1 演示原型目前侧重详情展示、快捷添加和采购入库，不应将“原型中尚未点击得到”误解为“产品不需要”。

### 6.7 库存状态判断

初版的基础库存状态：

| 状态 | 判断含义 | 常见展示 |
| --- | --- | --- |
| 状态正常 | 未触发库存异常规则 | 常规/正常标签 |
| 库存不足 | 当前数量低于该物品的最低库存数量 | 需补货提示 |
| 即将过期 | 有效期尚未结束，但已进入临期提醒范围 | 临期提示与剩余天数 |
| 已过期 | 已超过登记的有效期 | 过期提示 |

**状态呈现规则：**

- 已过期的物品应优先突出安全或处理提醒。
- 临期和库存不足可以同时成立，不能在数据上互相覆盖。
- 未填写有效期的物品显示“未设置有效期”，不直接判定为临期或过期。
- 库存阈值可以按照物品分别设置，不要求所有物品使用同一固定阈值。
- “库存不足”基于已登记库存，并不等于已通过摄像头实测了家中真实数量。

## 7. 清单页：从库存异常到采购行动

### 7.1 页面定位

「清单」专门承接采购相关行动，用于将库存不足及 AI 建议转化为待完成的购买任务。

### 7.2 页面结构

1. 页面标题“采购清单”。
2. 简短说明，例如“把库存不足转化为采购任务”。
3. **待采购清单**。
4. **根据库存推荐**区域。
5. 购买完成后的状态反馈或入库确认。

### 7.3 待采购清单

每条待采购记录建议包含：

- 物品名称及图标。
- 建议或待购买数量、单位。
- 当前状态，例如“待采购”。
- 操作入口，例如“已购买”。

**交互要求：**

- 用户可以将低库存物品加入采购清单。
- 已经在清单中的相同物品，不应重复生成完全相同的采购任务；可以提示已存在或允许修改原任务数量。
- 用户可以核对或调整计划购买数量。
- 采购完成后，应提供确认行为。

### 7.4 根据库存推荐

当存在物品低于最低库存阈值时，本区域展示补货建议。每条推荐可包含：

- 物品名称。
- 当前库存数量。
- 最低库存数量。
- 建议补货数量。
- “加入清单”按钮。

示例：

> 纯牛奶：当前 1 盒，最低库存 3 盒，建议至少补充 2 盒。

初版补货建议至少可以基于库存阈值生成；AI 管家后续可对建议原因进行解释，但不要求所有建议都依赖 AI 才能出现。

### 7.5 已购买与入库

建议正式产品采用两步确认逻辑：

```text
待采购 → 用户标记已购买
       → 核对实际购入数量
       → 确认入库
       → 库存数量更新、库存提醒重新计算
```

这样可以避免计划买两盒、实际只买一盒时，系统自动把库存增加两盒。

> **原型说明：** V2.1 目前通过“已购买”按钮简化演示增加库存。正式开发时应补充实际入库数量确认，确保库存准确。

### 7.6 清单为空的情况

当没有待采购记录时，显示空状态提示，例如“采购清单还是空的”，并引导用户查看“根据库存推荐”。不应只显示一大片空白。

本页面顶部必须显示 **“我的”**，不是“我的家庭”。

「我的」是个人中心，负责整合账号信息、家庭管理、库存规则、使用偏好和帮助信息；“我的家庭”仅是其中一个功能入口。

### 8.3 顶部个人信息卡片

展示头像、用户名或昵称，以及个人资料入口。

- 已登录用户：显示本人昵称或账号信息。
- 未登录状态：显示适当的访客提示。
- 点击个人信息卡片：进入个人资料或账号设置。
- 个人信息卡片不应替代下方的“账号设置”菜单；两处可以指向相同账号管理入口。

### 8.4 家庭与物品管理

#### 8.4.1 我的家庭

作为独立二级页面，负责家庭范围的信息。初版以**单家庭**为基础进行展示。

建议包含：

- 家庭名称。
- 家庭成员信息与协作入口。
- 家庭空间、存放位置列表，例如冰箱、厨房、储物柜、阳台。
- 可查看或管理已有存放位置。

家庭成员邀请、多家庭切换、多人实时协作属于后续增强方向，初版不必强行实现完整协作流程。

#### 8.4.2 库存检测规则

用于配置库存异常的判断条件。

- 每种物品的最低库存阈值。
- 有效期提前提醒天数。
- 低库存、临期和过期规则的说明。
- 规则调整后，相关库存状态应能重新展示正确结果。

页面需要解释规则的含义，例如“当纯牛奶少于 3 盒时提示库存不足”。

### 8.5 账号与个人设置

#### 8.5.1 账号设置

建议包含：

- 个人资料：头像、昵称及基本资料。
- 账号绑定信息：手机号、邮箱等（仅在产品实际支持时显示）。
- 登录与安全设置：修改登录信息、身份验证、安全管理。
- 退出登录入口（在已登录状态下）。

关键账号操作需明确确认或状态反馈，避免误触。

#### 8.5.2 通用设置

建议包含：

- 界面语言。
- 外观模式，例如浅色、深色或跟随系统。
- 常用计量单位与显示偏好。
- 应用数据与缓存相关的管理说明。

设置项应清晰显示当前状态；尚未开放的能力不应伪装成已经可以切换并保存的功能。

#### 8.5.3 消息通知

建议按消息类别展示开关或配置项：

- 库存不足提醒。
- 有效期临期提醒。
- 过期物品提醒。
- 产品或服务消息。

应清楚区分**App 内提醒**与**系统推送通知**；即使用户关闭推送，库存页面依然应显示真实库存状态。

#### 8.5.4 隐私与安全

建议包含：

- 隐私政策和数据说明。
- 相机、麦克风、通知等权限说明。
- 个人与家庭库存数据的查看、导出或删除入口（按实际支持范围提供）。
- 重要隐私和删除操作的二次确认。

### 8.6 支持与关于

#### 8.6.1 帮助与反馈

建议包含：

- 新手使用说明。
- 拍照添加、语音添加、库存查看及采购清单的常见问题。
- 意见反馈入口。
- 问题提交后的反馈结果提示。

#### 8.6.2 关于 MagicVVu

建议包含：

- 产品名称。
- 产品简介。
- 当前版本信息。
- 相关说明与必要的法律信息入口。

### 8.7 原型专用内容的处理

V2.1 HTML 的「我的」页包含“重置演示数据”，用于团队展示时恢复示例库存。**该按钮属于演示辅助操作，不是正式 App 个人中心的常驻必备入口。** 正式版本若需要清除数据，应在数据管理相关设置中明确说明并增加确认机制。

## 9. 页面之间的核心用户操作流程

### 9.1 询问库存情况

```text
打开首页
→ 查看 AI 管家卡片
→ 点击快捷问题或输入文本
→ 打开 AI 对话面板
→ 查看基于当前库存的回答与建议
→ 继续提问 / 关闭对话返回首页
```

### 9.2 拍照添加物品

```text
首页 → 拍照添加
→ 拍照或选图
→ 查看识别结果
→ 修改名称、数量等信息
→ 确认添加
→ 库存信息更新
→ 返回首页或进入库存查看
```

### 9.3 语音添加物品

```text
首页或库存 → 语音添加
→ 说出添加内容
→ 展示识别文字与提取的信息
→ 人工确认
→ 保存入库
→ 刷新库存列表与状态
```

### 9.4 处理低库存提醒

```text
首页最近库存状态 / 顶部提醒
→ 点击低库存物品
→ 查看物品详情和最低库存
→ 加入采购清单
→ 打开「清单」
→ 购买后核对实际数量
→ 确认入库
→ 库存状态重新计算
```

### 9.5 修改家庭库存规则

```text
我的 → 库存检测规则
→ 选择物品或提醒类型
→ 调整最低库存或临期提醒条件
→ 确认保存
→ 首页与库存页重新展示相应状态
```

## 10. 全局交互和展示规范

### 10.1 状态变化的一致性

凡是修改了物品数量、有效期、最低库存阈值或采购入库数据，相关页面应同步体现更新：

- 首页最近库存状态。
- 首页 AI 管家库存摘要。
- 库存页统计和列表。
- 顶部库存提醒。
- 清单页补货建议。

同一物品在不同页面的数量不能相互矛盾；AI 的回答也不应使用明显过时的库存数量而不提示。

### 10.2 操作反馈

| 操作状态 | 用户应看到的反馈 |
| --- | --- |
| 等待中 | 清晰的进行中状态，防止重复触发 |
| 成功 | 明确说明完成了什么，例如“纯牛奶已增加 2 盒” |
| 失败 | 显示可理解的原因，并提供重试或返回方式 |
| 无数据 | 说明当前没有内容，并指出可执行的下一步 |
| 输入不完整 | 在相应字段附近给出补充提示 |
| 重要操作 | 用户确认后执行，或提供撤销/恢复途径（如果适用） |

### 10.3 表单信息规范

- 必填项与选填项需要清楚区分。
- 物品数量应与计量单位同时出现，避免只显示一个无法解释的数字。
- 有效期应明确日期或剩余天数；未设置时显示“未设置”。
- 删除、清空、批量修改等高影响操作应有明确确认步骤。
- 新建与编辑页面允许取消，并清楚提示尚未保存的更改。

### 10.4 信息层级和视觉一致性

- 首页 AI 管家卡片具有最高视觉优先级，但不应挤压快捷添加按钮至难以发现。
- 拍照添加与语音添加并列、同等级，不要让其中一个看起来像次要文字链接。
- 低库存、临期、过期使用可辨识的状态标签；不能只靠颜色区分，应同时显示文字。
- 列表项具有一致的图标尺寸、标题样式、补充信息位置和点击反馈。
- 「我的」页按组展示设置，每行统一采用“图标 + 标题 + 简短说明 + 进入标记”的形式。
- 底部导航保持四个入口的可点按面积和视觉间距一致。
- 页面文字、按钮和信息卡片应适应常见手机宽度；内容较多时允许滚动，而不是裁切重要内容。

### 10.5 权限与可信提示

- 拍照前说明需要使用相机的原因；用户拒绝后提供允许情况下的替代录入路径。
- 语音输入前说明麦克风权限的使用目的。
- 无法识别时不能给出“添加成功”的错误提示。
- 对于 AI 生成的推断、建议或无法确认的结果，避免使用确定性的库存事实表述。

## 11. 初版开发范围与后续扩展边界

为了便于团队讨论，区分**当前布局已确定**、**初版功能目标**和**后续扩展**。

### 11.3 后续可扩展、尚未作为 V2.1 首页固定布局的功能

以下方向来自早期产品路线或功能规划，**不改变当前四栏导航，也不默认已在 V2.1 原型中实现**：

- **扫码录入：** 早期方案曾讨论过，但 V2.1 首页最终保留“拍照添加、语音添加”两个快捷入口。若首版需要扫码，可从库存页或添加流程中提供次级入口；是否纳入第一批开发由团队另行确认。
- **更多品类筛选及高级搜索：** 例如按存放位置、有效期范围、库存状态组合查找。
- **家庭成员协作：** 多用户共享库存、成员权限与协作记录。
- **主动 AI 提醒：** 根据用户偏好提供更个性化的补货和消耗建议。
- **采购历史与统计：** 完整历史清单、消费记录和趋势分析。
- **家庭空间可视化：** 将存放位置扩展为空间图或 2D/3D 视图。
- **更多外部服务：** 电商、智能家居设备等生态连接。

## 13. 文档结论

MagicVVu 初版最终采用**四栏底部导航**，以**首页内嵌 AI 管家**为最大特色，以**拍照添加、语音添加**为高频录入方式，并通过**最近库存状态 → 物品详情 → 采购清单 → 确认入库**形成家庭物品管理的基本闭环。

四个主页面的职责明确且互补：

- **首页：** 交互入口与状态摘要。
- **库存：** 全部物品及库存事实管理。
- **清单：** 采购计划与补货行动。
- **我的：** 个人、家庭及应用设置。

后续页面细化应优先遵循本说明书中已经确定的导航结构和首页顺序；对尚未确认的扩展功能，应先明确其所属页面，避免重复入口和无计划地增加主导航。
