# 中英文界面切换（v1.2.0-test）

## 使用方式

进入“我的 → 通用设置 → 界面语言”，选择“简体中文”或“English”。切换即时生效，不重启页面；重启应用后仍使用已选语言。首次使用默认简体中文，深浅色模式共用语言偏好。

## 本次范围

页面导航、登录注册、库存与采购、录入与详情、设置、提醒和助手的界面文案提供中英文。英文日期按英文习惯显示，数量使用英文单复数。

物品名称、位置、单位、个人资料、原有历史记录及 AI 对话保留原文。切换语言不改写库存、采购或设置中的业务值。AI 的语言策略、英文语音解析及英文字体设计属于后续工作；系统相机、系统照片选择器等界面仍由设备系统控制。

未修改后端接口、数据库、服务部署、AI 提示词或请求协议。

## 文案维护

- 默认中文：`app/src/main/res/values/ui_strings.xml` 与 `ui_extra_strings.xml`。
- 英文：`app/src/main/res/values-en/` 下的对应文件。
- Compose 通过 `rememberUiStrings()` 获取当前语言资源，使用 `strings.get(R.string.…, 参数)` 格式化文案。插入的用户数据作为参数原样传递，不做全文替换。
- `UiTextIds.labels` 兼容既有菜单、外观模式和分类的内部中文键，仅用于内置标签的显示。不可将用户输入的名称、位置、单位或对话内容传给 `strings.label`。
- 路由、筛选、状态计算及接口字段仍使用原值；不能把显示翻译结果用于业务比较或传给服务端。
- 新增文案时同时维护两种资源，保持格式参数一致。品牌名使用不可翻译资源。

## 语言保存与界面状态

语言偏好保存在本机 `magicvvu_v1` 的独立键 `ui_language`，允许值为 `zh-CN` 与 `en`；不会混入库存 JSON，也不会随账号切换上传服务器。

`AppLanguageProvider` 更新界面资源使用的语言，`UiStrings` 创建独立的资源配置，不改变系统默认 Locale 或替换 Activity 上下文。当前栏目、面板、筛选、滚动和未提交输入继续使用已有 Compose 状态。

## 验证

`AppLanguageTest` 使用独立的测试偏好文件，覆盖深浅色即时切换、持久化、切回中文、保留未提交表单、原样保留与 UI 文案同名的物品及位置、英文购买入库确认，以及英文录入与保存提示。原有中文导航、库存、采购及助手流程另做回归，不向真实家庭云端写入测试数据。

2026-10-24 验证：编译及 Android Lint 通过，32 项本地单元测试通过，17 项界面专项检查通过（16 项完整回归及 1 项录入补充检查）。541 条界面字符串的英文资源齐全，格式占位参数一致。模拟器的原有库存、采购和设置 JSON 与修改前完全一致，语言偏好单独保存；核对后恢复简体中文。
