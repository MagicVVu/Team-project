# App 与服务器联调

本次接通手机号登录、家庭创建/加入/切换、库存录入/编辑/消耗/删除、共享采购、按实际数量购买入库，以及服务器 P1 只读问答。服务端版本为 v0.8.0，迁移版本 `20261016_0006`。

## 直接体验

当前模拟器已经安装调试 APK，并登录专用调试账号；启动检查已通过。专用账号及家庭由管理员命令创建，自助注册仍关闭；账号凭据保存在本机 `.local/cloud-debug-account.json`，已加入 Git 忽略并设置为仅当前 Windows 用户可读写。密码不写入源码或聊天。请通过该文件查看手机号、密码和服务器地址。

模拟器的服务器地址为 `http://10.0.2.2:18080`。电脑需要保持 SSH 隧道运行：

```powershell
cd D:\project\Team_Project_Shared\frontend
.\tools\start-cloud-tunnel.ps1
```

脚本在后台启动 SSH，仅监听电脑回环地址：18080 对应正式服务，18081 对应临时隔离测试服务。已经有隧道时会提示端口占用；不要重复启动。进程 ID 保存在 `.gradle/cloud-tunnel.pid`，不用时可用 `Stop-Process -Id <进程ID>` 停止。

也可在终端直接保持运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18080:127.0.0.1:8000 magicvvu
```

App 进入登录页后输入手机号、密码与上述地址。登录后如果还没有家庭，会进入创建/加入页面；已有家庭则加载该家庭的数据。「我的 → 我的家庭」支持切换家庭、生成单次邀请码和加入家庭。邀请码 30 分钟有效。

## 数据规则

- 游客继续使用原来的本机库存和采购数据。登录不会自动上传、合并或覆盖游客数据；退出后恢复该本机空间。
- 登录后，服务器是家庭库存和采购的正式数据源。保存成功后重新读取服务器结果；断网或请求失败会明确提示，刷新核对后再操作。
- 各账号、服务地址及家庭的缓存互相隔离。前台每 30 秒自动刷新，也可点击同步栏的「刷新」；后台停止轮询。目前没有 WebSocket 推送。
- 库存使用版本号，其他成员修改后，陈旧的编辑/消耗操作返回冲突，需刷新重新确认。数量调整携带操作 ID，原请求重试不会重复扣减。
- 同名物品可以是不同库存批次。采购入库按实际数量建立新批次，保留旧库存；已购清单保留为历史。再次购买应新增采购项。
- 库存数量及最低库存最多六位小数；采购及实际购买数量最多三位小数。不同单位不自动合并。
- 删除库存为服务端保留来源及历史的移除操作；既有共享采购项不会随旧库存批次一起删除。清单只允许删除未购买项。
- 照片引用只保存在当前设备，不上传照片文件。外观、位置快捷项、提醒天数与提醒开关属于设备设置；库存最低阈值保存到服务器。
- 登录令牌由 Android Keystore 加密保存，密码不在 App 内持久化。会话过期需重新登录；当前手机号仅为未验证的登录标识。
- 云端 AI 根据服务器家庭库存回答，当前服务使用 rules 模式。AI 草稿不会直接执行库存写入；请通过库存和采购页面核对操作。

## 构建和验证

```powershell
$env:JAVA_HOME = 'D:\Android Studio\jbr'
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

调试 APK：`app/build/outputs/apk/debug/app-debug.apk`。发布版不提供默认 HTTP 地址，HTTP 调试地址仅允许 `localhost`、`127.0.0.1` 和模拟器电脑地址 `10.0.2.2`。真机公网使用需要另行配置 HTTPS。

新增设备测试：

- `CloudIntegrationTest`：真实 Android HTTP、Keystore 加密、会话恢复、两成员共享、版本冲突、安全重试、购买独立批次、家庭切换和游客数据保留。
- `CloudUiIntegrationTest`：通过真实页面登录、创建家庭、添加库存、加入采购、购买入库及查询已购历史。
- `DebugAccountSetupTest`：显式将管理员创建的调试账号安全登录到当前模拟器；仅在指定参数和应用私有交接文件同时存在时运行。

前两项测试必须显式传入 `cloudTestUrl=http://10.0.2.2:18081`，且服务健康接口的 `isolated_test` 必须为 true，否则拒绝写入。临时测试服务使用独立 PostgreSQL 内存数据，正式业务库不接受这些测试记录。测试服务在验证完成后清理，日常体验使用 18080。
