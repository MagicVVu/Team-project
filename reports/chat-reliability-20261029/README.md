# 聊天等待、停止反馈与恢复修复

2026-10-29，Asia/Shanghai。按用户后续说明，本次暂不接入 `inventory-autonomous-1`；保留 P8.4/P8.5 和最多两次模型调用规则。工作区原有未提交修改已保留。

## 已修改

- Android 聊天、会话初始化和原消息恢复读取等待从30秒调整为90秒；普通业务接口仍为20秒，连接等待仍为5秒。
- P8.5 的整轮 AI 阶段共享60秒预算，理解、确定性资料读取和表达均使用剩余预算；后端聊天入口等待上限75秒，处理锁90秒，避免长请求期间被重复接管。P8.4 仍使用原18秒内部预算。网关候选配置从60秒改为85秒。
- 后端公开 `dialogue.status` 和 `stop_reason`；资料不足提示补充资料，表达超时保留已持久化且核实的结果、回答、任务和草稿。理解尚无结果时，通过恢复提示明确说明超时或服务不可用，保留原请求，不重复调用模型。
- Android 分别展示补充资料、待确认、停止及未知状态；超时、资料不足、调用上限等原因转换为用户提示。停止信息独立于任务执行状态，不能据此判定执行成功。
- completed、processing、prepared、result_unknown 恢复均同步外层最新活动任务与会话修订。明确 null 清除引用；旧服务未返回字段时兼容原行为。本轮历史结果与最新活动任务独立保存。
- 完整恢复响应和 recovery_hint 持久保存；提示独立展示，避免后续任务详情读取覆盖。仅 prepared 且用户明确点击恢复时，才允许按原请求体继续；未知阶段不重发。
- 明确被服务器拒绝的消息保存 messageRejected 标志，输入框据此保留原文；409会话冲突刷新后不自动修改原请求或重新发送。401/403权限失败同样保留输入。
