# 新增库存相似名称归类

日期：2026-10-28

## 使用行为

在云端库存新增物品（手动、语音逐项确认、照片确认）时，先向当前家庭后端查询名称候选：同名，或存在连续两个及以上相同 Unicode 字符。名称比较统一 NFKC、去首尾空白、忽略大小写；只有一个相同字符且不完全同名不匹配，非连续相同字符不匹配。

有候选时展示专用弹窗：“检测到您库存中已经存在…物品，是否归为同一类物品？”多个候选可单选一个。

- 是：复用所选批次已有商品；旧批次尚无商品时，同时为旧批次和新批次建立同一商品。
- 否：新物品单独建立商品，即使完全同名也不自动合并。
- 无候选：用户确认添加后自动建立独立商品。
- 取消：不新增库存，不修改商品。

商品名为该组库存批次中最短的名称，各批次原名称保留。圆环数量为所有关联批次的数量总和，日期取全部关联批次最早的已登记有效期；质量、体积等有确定关系的单位会可靠换算，不能换算时显示数量待核对，详情保留原数量单位。独立商品保留单批次的位置、阈值、日期和照片等展示信息。

归类适用于新建库存。没有批量改写历史未归类库存；用户以后选择这些旧批次归类时会一起关联。采购入库和 AI ADD 也确保新批次有商品；采购明确关联的来源继续继承已有商品。编辑组内库存名称会重算商品最短名。

## 协议与一致性

GET /api/v1/households/{household_id}/inventory-product-matches?name=...&limit=200&offset=0

返回 inventory-product-matches-1、items、total、limit、offset、next_offset。包含候选库存 ID/名称/版本，及已有商品 ID/名称/版本。

POST /api/v1/households/{household_id}/inventory-items 保留原库存字段，新增 product_grouping：

- {"mode":"separate"}，省略时也默认独立商品。
- {"mode":"existing","candidate_inventory_item_id":"UUID","expected_inventory_version":1,"expected_product_version":1}。候选没有商品时省略商品版本。

新库存、商品、关联、回执和业务事件在一个事务中提交。后端重新验证家庭、匹配和版本；冲突时回滚。重复提交原 ID 和原正文返回同一结果；更换归类选择被拒绝。旧版本普通创建的请求哈希和回执仍兼容。

前端在发送前持久保存原请求，超时、服务异常、认证失效或请求身份冲突不丢失恢复信息。恢复按原请求发送，按服务器、账号和家庭隔离。编辑流程不触发新增弹窗。
