## 1. 注册开关的实际含义

仓库与线上镜像的 `app/routers/auth.py` 均在 `/api/v1/auth/register` 首先读取 `AUTH_ALLOW_UNVERIFIED_SIGNUP`。值不是 `true/yes/1` 时直接返回 403，尚未进入账号创建逻辑。这是之前无法自助注册的服务端原因。

启用后不要求短信验证。注册仍执行手机号格式归一化、唯一性检查、密码长度校验和 Argon2 哈希存储，并明确写入 `phone_verified_at=None`；API 返回 `phone_verified=false`。未把未验证手机号伪造成已验证身份。

登录继续校验账号密码，签发可注销的 Token。手机号仅作登录标识，不提供手机号所有权证明；当前没有公开的手机号找回/重置密码接口。个人资料更新仅允许昵称，修改手机号请求会被拒绝；家庭权限需要现有成员关系或有效家庭邀请，不因手机号相同或未验证而自动授予。

## 3. 客户端限制如何调整

旧提示「调试包只能写入已验证的隔离服务」来自 `TargetPolicy.health()`：它比较构建的 `CLOUD_EXPECT_ISOLATED` 与服务器 health 的隔离标记。以前 debug 固定为 true，而共享服务器实际为 false，因此注册、登录及所有写入都会在客户端预检阶段被阻止。

现在地址与环境策略仍集中在 Gradle、`TargetPolicy`、`CloudApi` 和 `AgentClient`，没有在各业务页面散落例外：

| 模式 | 构建参数 | 默认地址 | 预期服务器标记 |
|---|---|---|---|
| 日常统一 debug | 无需额外参数 | 阿里云 HTTPS :8000 | false |
| 显式隔离回归 | `-PmagicvvuIsolatedTest=true` | `http://10.0.2.2:18081`，可用原 `magicvvuApiUrl` 显式指定 | true |
| release | 保留原 `mewstowReleaseApiUrl` 机制 | 默认空；未配置即拒绝联网 | false |

服务版本和执行协议检查仍保留，显式隔离测试仍拒绝共享服务器。未删除登录、Token、家庭成员鉴权、版本冲突检查、数量验证和重要写入确认。不存在按普通测试账号强制只读的角色开关；API 与 App 实测均可写自己的家庭。

公网 TLS 和主机名校验保留。公共测试 CA 移到 `src/debug/res/raw/magicvvu_test_ca.pem`，只对指定服务器 IP 生效；release APK 不含该 CA。网络配置仅为显式隔离回归保留回环 HTTP 域，日常构建地址策略拒绝这些 HTTP 地址，没有放开任意公网明文 HTTP。

Agent 正常库存问答已实测返回 answered。跨提问引用、自动预测采购等现有协议能力限制不等于测试构建门禁，本轮未扩大其业务权限或让 Agent 匿名写入。

## 8. 快速恢复注册限制

```bash
sudo python3 /etc/magicvvu/ip-direct/set_signup.py --allow false
# 需要重新开放团队注册时
sudo python3 /etc/magicvvu/ip-direct/set_signup.py --allow true
```

该工具先建立 root 专属配置备份，只在配置或容器值不一致时执行 `docker compose up -d --no-deps backend`；不更换镜像、不操作数据库卷、不改白名单。关闭注册后不删除现有账号，已有用户的登录和家庭权限机制不变。

没有在团队正在测试时切回 false 做额外停用演练；本轮实际验证了工具 `--allow true` 的无变更执行、配置备份及运行值检查。恢复脚本和源码保留 false 的明确分支。

本阶段仍是受控团队开发测试，不代表手机号已验证、正式上线或其他合规事项已完成。TLS、账号密码认证、Token、家庭隔离、参数校验、服务器密钥保护、数据库持久化和备份能力均保留。
