# 交互状态规格

负责人：summerdong2006-dot 定稿视觉原型；本包提供可运行工程原型与行为规则。`agent/demo/index.html` 包含录入、库存 / 批次详情、事件与采购四块，不要求正式页面复制其视觉样式。

| 状态 | 展示 | 操作与下一状态 |
|---|---|---|
| 等待输入 / 空库存 | 输入框、明确“尚未变化”；库存空态引导新增 | 输入文字或手动填写 |
| 请求处理中 | “正在处理，库存尚未变化”；防止重复点击 | 等待结果；输入保留 |
| needs_clarification | 缺字段或多个真实批次，显示数量 / 单位 / 位置 / 版本 | 填表或显式选择批次；不得默认替用户选第一批 |
| needs_confirmation | 编辑名称、数量、单位、位置和日期；“尚未写入” | 保存草稿、取消、确认；编辑增加 revision |
| 提交中 | 禁用重复操作，保留同一幂等键 | 返回事务结果后更新页面 |
| 已写入 | 显示新库存、事件及 trace_id | 对最新事件显示撤销入口 |
| answered | 显示工具查询结果，多个批次逐个展示 | 继续输入；未知位置显示待定位，日期显示未知 |
| unsupported | 说明一次单物品与当前支持能力 | 修改输入或手动填写 |
| 模型 error | 保留原输入，解释可重试 / 手动填写 | 不显示已写入；不自动付费重试 |
| 字段校验失败 | 说明具体问题，不清空草稿 | 修改后重新保存和确认 |
| VERSION_CONFLICT | 显示库存已变化，要求重新核对 | 获取新库存、重新选择批次 / 校验、明确确认，不自动扣减 |
| 网络提交结果不明 | 保留待提交 revision 与幂等键 | 重试同一请求取得原结果，不能以新键重做 |
| 已取消 | 提示库存未变化 | 重新录入 |
| 撤销成功 / 不可撤销 | 展示 Correction 或后续变更提示 | 刷新库存与历史，保留原事件 |
| 采购清单 DRAFT | 数量单位可修改、行可删除 | 保存或确认；不影响库存 |
| 采购清单 CONFIRMED | 只读，显示已确认 | 新采购项开启新清单，不触发入库或下单 |

关键文案统一“草稿”“已确认”“已写入”。模型输出 `needs_confirmation` 不能被前端解读成已完成。服务已成功提交但后续刷新失败时，应保留提交成功提示及事件标识，刷新读取失败不能被描述为写入失败。

工程页默认规则模式，可切换真实 DeepSeek 或模拟失败；页顶始终标记 MOCK。正式原型交付应附链接 / 导出图及这些状态的按钮行为，当前没有虚构 Figma 文件或正式视觉定稿结果。
