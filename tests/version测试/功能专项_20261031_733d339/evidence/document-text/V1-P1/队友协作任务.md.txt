# V1-P1 队友协作任务

状态：待开发。本文件只分配本阶段开封、整批移动、丢弃和澄清续接的协作工作。AI 任务另见 [AI 开发任务](AI开发任务.md)。

## 1. CaviarHidon：新动作前后端与数据接入

| 任务 ID | 要做的事情 | 交付与通过条件 |
|---|---|---|
| P1-BE-01 | 扩展批次字段和事件模型 | Batch 增加 nullable `opened_at` 和 DISCARDED 结束状态；Event 增加 Opened、Moved、Discarded；提供迁移及种子脚本，开封日期与库存结束状态分开存储 |
| P1-BE-02 | 实现三个新动作的确认事务 | 开封 / 移动数量不变，丢弃不超库存；同事务更新批次、事件、草稿及幂等结果；重复开封 / 原地移动不重复写事件；事件失败整体回滚 |
| P1-BE-03 | 保存澄清任务并接入续接接口 | 实现 `POST /api/v1/agent/clarifications/{id}`，提交 `{revision, answers}`；任务绑定用户、家庭、原文、解析字段、候选、修订号和有效期；补字段后调用 AI 续接，返回澄清 / 草稿 / 错误 |
| P1-BE-04 | 提供新字段和批次只读接口 | search 返回新增字段；提供 `GET /internal/v1/inventory/batches/{id}`；新接口校验家庭归属，不接受客户端指定身份或库存版本 |
| P1-BE-05 | 扩展新动作的撤销和事件统计 | 最近变更撤销追加 Correction 并恢复日期 / 位置 / 数量 / 状态；有后续变更时拒绝直接恢复；Discarded、Opened、Moved 不作为消费 |
| P1-FE-01 | 实现本阶段页面及交互 | 开封日期、目标位置、丢弃数量 / 全部选择、批次选择、补字段、草稿编辑确认、事件与撤销页面可操作；呈现提交、失败、过期及冲突状态 |
| P1-FE-02 | 接入本阶段正式接口 | 页面走业务后端，AI 密钥不进入浏览器；展示真实开封日期 / 位置 / 状态；版本变化展示当前事实并要求重新确认；补字段不自动执行变更 |

需要 AI 提供：新动作 schema、校验规则、AI 续接接口、成功 / 失败示例、错误码和种子数据。交付：新动作前后端代码、迁移脚本、接口文档、联调环境和本阶段演示。

## 2. summerdong2006-dot：新动作与澄清交互原型

| 任务 ID | 要做的事情 | 交付与通过条件 |
|---|---|---|
| P1-UI-01 | 设计开封、移动、丢弃表单 | 开封显示绝对日期；移动明确整批和目标位置；丢弃明确数量 / 全部及不可作为消费；不要求开封 / 移动填写数量 |
| P1-UI-02 | 设计批次选择和补字段续接 | 候选显示批次、数量、位置、开封日期及版本；无默认选择；补字段后进入待确认草稿，保留原文与已填写内容 |
| P1-UI-03 | 设计变更对照、事件与撤销 | 展示变化前后值和目标批次；开封 / 移动强调数量不变；丢弃展示减量；撤销有明确对象与结果 |
| P1-UI-04 | 覆盖本阶段异常状态 | 重复开封、原地移动、多批次、终态、超量、日期错误、澄清过期、版本冲突、模型失败及重试都有说明与可操作入口 |

需要 AI 提供：字段、澄清结果、五种 AI 状态、错误码与工程演示。交付：可走通的交互原型、字段 / 按钮说明和状态规格；页面代码由 CaviarHidon 实现。

## 3. Garin-cyber：本阶段样本复核与验收

| 任务 ID | 要做的事情 | 交付与通过条件 |
|---|---|---|
| P1-QA-01 | 人工复核本阶段 150 条样本 | 核对意图、日期 / 位置 / 数量、候选批次、是否澄清、允许动作和来源；90 开发 / 60 保留，同表达改写归同集合；记录复核人和日期 |
| P1-QA-02 | 验证三种动作与事件 | 开封 / 移动数量不变；部分 / 全部丢弃状态正确；重复开封 / 原地移动无重复事件；丢弃不计消费；日期、单位、终态与超量校验正确 |
| P1-QA-03 | 验证澄清与确认异常 | 选择 / 补字段可续接；未确认不写库存；任务过期、乱序修订、跨家庭、库存并发变化受保护；提示注入与模型失败不执行变更 |
| P1-QA-04 | 验证新动作事务与撤销 | 重复确认返回同一结果；同版本并发最多一次成功；事件写失败全部回滚；撤销恢复完整状态，有后续变更拒绝直接恢复 |
| P1-QA-05 | 复核模型结果并执行正式演示 | 意图准确率 ≥90%、澄清召回 ≥95%、线上 P95 ≤10 秒；保留真实失败记录；正式环境完成“开封 → 整批移动 → 丢弃 → 查看事件 → 撤销”，重启后数据与幂等结果仍在 |

需要 AI 提供：本阶段样本、工具上下文、期望动作、评测命令和逐条结果；需要 CaviarHidon 提供联调环境与故障注入方式。交付：人工复核记录、冻结保留集、用例、失败复现及正式验收报告，注明运行环境与提交版本。

## 5. 协作顺序与共同完成标准

1. AI 给出新动作字段、规则和接口草案；CaviarHidon 核对数据与接口，summerdong2006-dot 核对页面状态，Garin-cyber 核对验收，Gracie1103 统一需求文档。
2. 前后端、AI、原型、样本复核和文档并行推进，接口调整同步更新对应交付物。
3. 用本阶段种子数据联调开封、整批移动、部分 / 全部丢弃及澄清续接，再验证异常、撤销与持久化。
4. 验收报告分别记录 AI 实测、Mock 演示与正式新动作链路的结果；未执行的检查保持待验收，不填通过。

共同完成标准：本阶段的新动作能够从文字或澄清补充进入可编辑草稿，经用户确认后在正式数据库中保存批次和事件，页面展示正确结果，并通过重复操作、失败回滚、版本冲突和撤销验证。
