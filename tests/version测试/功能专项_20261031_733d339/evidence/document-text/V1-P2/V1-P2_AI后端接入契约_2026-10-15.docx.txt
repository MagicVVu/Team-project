2 调用方向与认证
调用顺序为 App → 业务后端 → AI → 后端只读库存 → PostgreSQL。AI 仍监听 Docker 内网 agent:8767；无需向公网开放 AI 或数据库端口。

Backend 到 AI

数据与版本要求
新字段存储在批次或商品资料中均可，但只读返回值应表达当前批次的有效事实。影响风险判断的事实变更应推动版本更新或提供等价可追踪机制；规则变化另由规则版本记录。具体迁移基于真实 schema 和当前 head 增量实施，不修改历史迁移。
兼容发布顺序
原 P1 Batch 严格拒绝未知字段。先运行可接受旧字段的 P2，再让后端输出扩展字段；回滚 P1 前先关闭扩展输出。长期并行 P1/P2 时须做版本化投影或能力协商，不能假定 P1 会忽略新字段。
当前生产规则没有商品专属开封天数。即使七个字段已接齐，缺少 product_id 对应的真实包装规则时仍须提示 after_open_rule，不宣称所有商品均可判断开封期限。
日期边界按家庭本地日期计算：use_by 与 expiry 在超过标签日后触发，同日仍可提醒；best_before 只提示品质日期。商品开封窗口在 opened_at 加规则天数的当天提示核对，不按小时推断，也不延长原标签期限。

6 业务响应与结果保存
AI 的 /agent/message 返回裸 AgentResult，业务网关负责外层任务结构。共有字段包括 status、intent、reply、trace_id、original_text，以及 draft、preview、candidates、facts、missing_fields、clarification、error_code、retryable、manual_entry、trace。P2 进一步增加 risks 和 evaluated_count。
后端应完整保留 result JSON，不根据 HTTP 200 判定业务成功。GET 任务恢复应保留风险事实、证据、版本与评估时间；历史结果是当时快照，不能作为重新读取的当前判断。

续接约束
风险协议仅允许 name，意图固定 QUERY_RISK；不接受标签、日期、位置、数量、家庭、版本或规则修改。
有效期为原始创建后 15 分钟；补充不延长期限。修订必须匹配服务端最新值，接受补名称后修订递增。
名称续接重新读取最新库存，同名批次分别评估，不默认选第一批；不调用第二次模型。
旧 P1 context 原样兼容，原有批次选择和补字段流程保留。原始 context 只能由可信后端保存和传回。
对 App 公开的 clarification 仅含 revision、allowed_fields、expires_at。工具超时会保留已补名称、新修订和原有效期；现有后端对 error 状态的续接限制见下一页，不能声称已完成超时后的真实恢复验收。
9 错误 幂等与待接入事项
消息及结构化续接在处理故障时可能返回 HTTP 200 + status=error；直接评估的工具故障或总超时以 HTTP 503 错误 envelope 返回。请求认证失败 401、结构校验失败 422。App 与后端须分别处理 HTTP 状态和任务状态。

AGENT_TIMEOUT

TOOL_UNAVAILABLE
临时依赖故障；由明确用户操作和任务恢复策略处理。
TOOL_UNAUTHENTICATED

幂等与恢复
AI 初次处理、结构化续接及直接风险评估分别采用 10 秒总截止时间，包含模型与工具读取；单次库存 HTTP 读取超时为 5 秒。失败保留原文与已填信息，不自动付费重试。
后端按用户、家庭、request_id 去重。同键同输入返回已保存结果，同键不同内容 409；时区及今后开放的 reminder_days 都应纳入输入指纹。13 秒 HTTP 超时与 30 秒处理租约需联合验证；租约到期不代表上一次供应商调用必然未发生。
待协同：现有澄清路由只接受 needs_clarification。AI 返回 error 时即使保存了 context，也不能直接续接。建议仅对带最新 context 且 retryable=true 的 error 任务开放用户显式结构化恢复，继续校验身份、期限、修订和白名单；此建议尚未实现。
另需补齐：七个风险事实字段；非默认 reminder_days 的转发及指纹；专用真实测试身份与库存；规则人工复核。基础 P2 结果与名称续接已经过源码兼容核对，不需要另建一整套网关。
