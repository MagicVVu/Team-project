# V1-P5 开发规划：统一任务接入与语音文字闭环

日期：2026-10-16。AI侧已按本规划实现，证据见[交付记录](delivery-and-validation.md)。用户进一步明确服务器数据库网关适合本项目、不需要改动，因此实施以现有v0.6协议兼容为准：语音元数据留调用端，不要求新增网关字段或接口；当前不支持的能力明确禁用。手机接入和正式发布尚未完成，以下保留规划依据。

## 1. 目标与范围

建议把 P5 定义为：**用户说话后先核对转写文字，再进入与键盘输入相同的文字任务、澄清和待确认草稿流程**。先统一事实来源、身份和任务协议，避免在旧手机快照协议上叠加新功能。

首版采用已有设备系统识别入口，AI 只处理最终确认文字，不新增自建 ASR、音频上传服务或 /voice/transcribe。设备服务不可用时允许手动输入同一份文字；用户须知道正在使用本机模式还是在线家庭模式。

P5 的 AI 路径继续只读库存、生成草稿。确认后业务写入、事件持久化、幂等及撤销由业务后端完成，不能由 LLM 或语音回调调用本机写入来代替云端事务。沿用现有页面，不新增 Mock、假库存、假事件或演示页面。

保留单物品、单动作边界。现有本机语音页可逐项录入多个物品，但在线 AI 首版面对多物品/多动作提示分次提交；不把用户原话静默拆成多次付费调用或多张草稿。

## 2. 分阶段开放能力

| 能力 | P5 处理 |
|---|---|
| P0/P1 文字操作 | 复用现有 AI；客户端按 action 正确承接字段，后端具备确认能力后才开放业务保存 |
| 语音转写 | 识别、展示、编辑、用户提交；支持取消和手动回退 |
| 结构化澄清 | 复用服务端 task/revision；候选完整展示，不调用第二次模型选批次 |
| P2 风险问答 | 后端事实字段和规则条件满足时开放；缺事实明确待核对 |
| P3 统计/预测/补货 | 后端规划接口、item_key及依据保存达到条件再开放，未就绪不伪造历史 |
| 云端确认、事件、撤销 | 后端共同验收项；未实现时停在“草稿尚未写入” |

P5 不以全部 P2/P3 数据工具完成作为语音文字适配器开发的前置条件；但不能用适配器完成替代整个 V1 的真实链路验收。图片识别、RAG、后台主动提醒、复杂预测、长期记忆、多 Agent 拆分、电商下单不纳入。

## 3. 先统一正式任务协议

在线模式采用正式后端鉴权用户、家庭权限和数据库事实，不上传手机 items 冒充家庭库存。不将服务 token 发给 App。客户端连接迁移时依据已核对的真实接口：

- POST /api/v1/agent/messages：household_id、text、request_id、household_timezone。
- GET /api/v1/agent/tasks/{task_id}：读取已有任务和恢复结果。
- POST /api/v1/agent/clarifications/{task_id}：revision及允许的 answers，由后端恢复内部上下文。
- GET /api/v1/drafts/{draft_id}：读取待确认草稿；当前不是确认写入接口。

当前 Android 发送 inventory_revision/items、解析 expected_revision/engine/data，不能直接指向同名正式消息路径。建议前端维护者新建明确的业务任务客户端并迁移调用，保留旧本机快照网关为历史兼容材料；不要自动尝试两套协议或在网络错误后切到本机写入。

客户端需保存 task_id、request_id、revision、draft_id、trace_id及当前家庭。候选保留完整名称、数量、单位、位置、日期、状态、版本；批次选择用 batch_id，P3 商品选择用 item_key，不互相冒用。

草稿按 action 分型：OPEN/MOVE 无需 quantity，OPEN 有 opened_at，MOVE 有 to_location，DISCARD 有模式和实际数量；不能继续全部强制数量/单位。P3 planning_basis 独立保留。无法承接的动作显式禁用并说明，而不是丢字段或转成 ADD。

游客本机记录不自动上传、合并到云端家庭。在线数量和状态只由后端确认结果刷新；本机模式继续明确显示“本机记录”。日期等原有字段的持久化缺口由前端一并核对。

## 4. 语音与编辑状态

建议前端使用可取消的单次输入会话，状态为：待输入 → 等待识别 → 待核对文字 → 提交中 → AI五状态。识别取消/失败回到可编辑文字；任务请求超时保留原文并允许查询原任务。语音会话状态不新增到 AgentResult 的五种业务状态中。

1. 仅用户主动开启设备识别，不自动录音或后台监听。
2. 识别结果先展示原文，允许修订；仅取到结果不能自动发送 AI，更不能自动入库。
3. 用户点击提交后，以最终文字作为 AI original_text 和字段依据。未经确认的识别原文不能为被删除字段提供证据。
4. 保留端上原始转写和最终文字，标记是否人工修订；只在后端明确扩展任务元数据后按需传递，不擅自向现有严格 Message 塞新字段。
5. 不上传原始音频、不长期保存录音。若将来更换云端 ASR，需要单独评审数据流、保留策略与供应商，不能视作本规划已授权。

source=voice、input_session_id、transcript_revision、user_edited 等可作为拟议的业务输入元数据；不参与库存数量计算，不作为用户身份或可信时间。第一版可只保存在端上，不要求新增 AI 服务或声学意图。

设备当前代码没有使用识别置信度；缺值保持缺失，不编造百分比。数量、单位和动作最终都须由确认文字或只读工具事实证明。系统不能保证纠正用户未发现的 ASR 听错，验收需区分“相对确认文字的字段正确”与“相对真实语音的识别正确”。

## 5. 防误处理与恢复

- 否定、自我修正、引用他人话、犹豫或模糊数量不能靠删语气词变成确定命令。“不、别、不要”等词必须保留，口语规范化不改变含义。
- 一次录音对应 input_session_id，重录或离开页面后作废旧回调；过期结果不得覆盖新文字。提交按钮防重复，多次回调不能创建多次模型请求。
- 一份已提交的最终文字固定 request_id；断线重试同键同内容，禁止每次网络尝试生成新 UUID。改变文字须形成新请求，不能用旧幂等键改正文；旧草稿在手机端作废，后端取消/失效机制需共同定义。
- 请求超时不代表服务端没处理：优先用已保存 task_id 查询，或按后端允许的同键恢复机制读取。禁止超时后直接再走另一个引擎、自动付费重试或写本地副本。
- 同名批次、缺日期/单位等复用结构化澄清；动作、家庭和库存版本不能从答案修改。改动作属于新消息。
- 用户核对过转写并不等于确认业务写入。库存/清单草稿仍需单独确认，保存成功以业务事务响应为准。

初始 AI 和每次澄清仍分别执行覆盖模型及工具的10秒总截止。识别耗时独立测量，不并入模型10秒。后端调用、客户端总等待和任务恢复窗口共同配置并验证，不能仅把连接超时与读超时之和当成严格总截止。

## 8. 验收设计

保留全部 P0–P4 用例、旧预期及差异记录；新增 P5 专项回归，不能为提高分数更改冻结答案。新增150条文本流程样本，90开发/60保留，按表达场景组隔离，标明构造来源及人工复核状态；口语合成文字不能算真实 ASR 准确率证据。调整提示或解析逻辑后，冻结新代码和数据版本再运行独立保留验证。

建议门槛：

- 意图准确率≥90%，需要澄清场景召回≥95%；对最终确认文字，待确认草稿字段及边界处理全部正确。
- 未确认、取消、否定、跨家庭、超量、旧版本、过期上下文和多操作场景不写库存/清单。
- 同一最终文字首次提取至多一次真实模型调用，结构化续接为0；重复回调、重连不重复创建业务效果。
- AI+只读工具完整流程 P95≤10秒；手机端与识别耗时另列，不冒用本地夹具毫秒数为真实链路性能。
- 在后端具备确认能力时，确认一次只产生一次业务效果；冲突重新核对、取消无变化、重启能恢复已确认结果，由事务/审计证据支撑。

真机验证建议先收集至少30条经同意录制或现场核验的真实语音，覆盖至少3位说话者，并在至少2种真实设备/识别环境记录结果；不足时明确范围，不能声称代表广泛用户。原音频默认不入库、不提交 Git；标注保留脱敏转写、设备/识别环境及审核状态。报告识别字符错误、物品/数量/单位/否定词错误、用户修改率、完成率和识别耗时；ASR通过阈值需采集真实基线后共同冻结。

必须覆盖：空结果、无识别服务、用户取消、网络失败、重复/迟到回调、重录、文字编辑、重复点击、退出与重新进入、应用重建、同名批次、数量口误、日期含数字、多物品、指代澄清、引用或否定、任务超时但服务端已完成、旧草稿确认冲突，以及在线失败后不得静默本机写入。没有设备/正式环境的项目记为未覆盖。
