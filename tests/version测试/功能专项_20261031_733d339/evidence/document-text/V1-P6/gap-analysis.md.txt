# V1 AI 范围与完成情况核对

核对日期：2026-10-16。本文件记录开发前的规划分析基线；随后用户授权除Jev外的P6开发，最新结果见 delivery-and-validation.md。原始分析结论与当时证据保留。

## 1. 依据与判定方式

原始依据为本地 `V1/完整版本规划/CS353_V1_AI_Agent详细规划.docx`（2026-10-03）第 3—12、15—19 章、同目录后端协同规划，以及 `总体规划/CS353_AI_Agent系统总体规划.docx` 第 3、6 章。另核对 2026-10-10 的 UI 缺口文档、P0—P5 阶段契约/验收、实际 Python 代码和本轮远端 OpenAPI。原始 Word 不在此 Git 仓库内，本文件保留其章节和要求摘要，方便克隆仓库后的复核。

用户后来明确的边界优先：数据库网关不改；只同步 AI 运行代码；AI 不直接写库存；多 Agent 拆分从 V1.5 开始。原 Word 的 Spring Boot、独立 ASR 接口等技术建议不要求替换现有 Python 后端和 Android 系统识别。

区分四种状态：已有 AI 实现；AI 能力缺项；已有代码但接入/验收欠项；非 AI 责任。不能将 P0 内存演示的确认/撤销、Python 会话参考实现或离线合成样本视作正式产品闭环。

“无数量的用完”和“按位置看物品”属于当前冻结阶段之后需要补齐的 V1 能力；不能把它们描述为 P1 原约定未完成。原 Word 允许少量历史给粗略估计，P3 冻结为更保守的最低窗口门槛；P6 保持当前门槛，短历史展示统计与不足原因，不为凑齐功能放宽成未经验证的预测。

撤销/纠错是 V1 产品要求，原规划没有强制以自然语言聊天执行。P6 优先完成明确事件对象的业务入口协作与验收，不擅自增加 UNDO/ADJUST 写命令或让模型直接恢复数量。

## 4. 2026-10-16 远端新基线

本轮通过已配置 SSH 只读检查，不读取密钥内容/运行令牌，不创建用户或业务数据，不修改服务器文件。

- 正式后端版本 **0.8.0**，health=ok，ready=ready，database=ok。P5 文档的 0.6.0 是当时记录，本轮不覆盖历史。
- 已有内部库存 search(name) 和 get_batch；源码显式限制最多 1000 条，超出返回冲突而非静默截断。可为限定规模的完整位置筛选提供依据。
- 已有公开 POST 消息、POST 澄清、GET 任务、GET 草稿。澄清仍限定非空答案、原 9 个字段，不包含 item_key。
- 已有共享采购清单 GET/POST/PATCH/DELETE 及 purchase 路由。purchase 的契约返回库存对象及 newly_stocked，源码说明同事务标记已购并创建库存；本轮未调用该写接口，事务正确性未实测。
- 未见同快照 planning/context、语义消费事件读取、AI 草稿确认或逆向撤销路由。已有库存 CRUD/adjustments 不等同于这些能力；不据此推断所有数据库内部实现都不存在。
- 内部库存转换器返回 P1 基础字段，包括 opened_at；未返回 P2 扩展的 category、label_date_type、label_context_valid、storage_condition 等。AI 必须继续按未知处理。
- 网关任务保存完整 AI result；AIDraft 单独保存 command_json、preview_json。planning_basis 能随任务结果保留，不等于独立草稿确认时已有依据校验。执行方需关联原任务并验证完整依据。
- 当前采购条目有 source_inventory_item_id，可作核对线索，不能在未确认映射/快照完整性前，把它当 P3 的商品级 item_key；公开 JWT 接口也不能直接改用内部 service token 调用。

因此 P6 不再把“采购清单完全没有接口”列为缺口，但仍需解决 AI 到真实历史、偏好、待购项的可信聚合。

## 5. 尚未通过的验收

P5 规则保留集 60/60，真实模型 59/60 完整检查；“牛奶什么时候用完”曾出现 INVALID_MODEL_OUTPUT，系统正确拒绝且未写入。草稿字段 24/24 正确不代表所有流程通过。P2 也保留过模型格式错误；P3 的 60/60 只覆盖当时独立合成集合。

样本主要为 AI 构造、未人工复核；风险规则只有 source_check；本地模型 P95 不含真实手机/网关/数据库。源码同步、可导入、健康正常分别只证明对应层，不证明实际模型版本、真机语音、事务或预测效果已经上线通过。

## 6. 后续版本边界

不纳入 P6：LLM 多 Agent 联合工作、联网/RAG、图片扫码、EWMA/个性化训练、长期记忆、后台扫描/推送、What-if、IoT、电商下单。按需首页摘要不是后台主动提醒；多商品只读摘要不扩大单物品单动作写草稿边界。

Jev 是原始V1架构中的真实缺口。用户在本规划之后于2026-10-16明确“jev可以先不用实现”，已构成本轮范围调整：P6只实现实际决策记录，Jev暂缓、不作为本轮门槛，也不声称已完成原双模型接入。
