# P7 验收与验证记录

## 自动化与评测口径

完整 AI 测试包括 P0～P6、运行配置及 P7，656 项通过、1 项 Windows 符号链接权限跳过；本轮 P7 专项 86 项。旧网关 4 项通过，正式后端本地回归 40 项通过。测试使用只读库存夹具、内存 HTTP、临时测试数据库与可控时钟，不连接正式库存或执行正式事务。

P7 独立样本 150 条，50 个场景组，每组 3 条，开发 90／保留 60，场景组不交叉。来源均为 AI 构造，人工复核 pending，不是真实用户/语音。旧数据和结果保留。规则与真实模型结果分别记录，不互相替代。

逐条检查意图、状态、原文、完整草稿字段及前后预览、目标批次/版本、事实对应、零写入、首次至多一次提取、续接零模型。四种完整澄清流程包含序号、日期、数量单位和库存变化后重选。

命令在 agent 目录运行，PYTHONPATH 同时包含 agent 与仓库根：

```powershell
python -m pytest tests -q --junitxml=../docs/versions/V1-P7/ai-tests.xml
python -m eval.conversation.run --engine rules --split dev
python -m eval.conversation.run --engine rules --split test
python -m conversation.export_contract
```

Windows 当前沙箱不能初始化 asyncio 的本地事件循环，测试经授权在沙箱外运行。首次完整测试因未包含仓库根而发生旧网关导入失败，修正 PYTHONPATH 后回归通过，未为此修改产品代码。

正式后端测试最初因主 Python 缺少 SQLAlchemy/alembic 而收集失败；之后将仓库原有 requirements-dev.txt 安装到项目 .cache 的隔离环境，使用原 Python 3.13.5，未修改全局环境或依赖清单。Windows 共享临时目录权限问题通过项目内全新 basetemp 解决，40 项全部通过。正式服务器数据库及 Android 联合验收仍待业务方执行。

真实模型开发集首轮 89/90：一条“这个消耗”被理解为消费统计查询。保留该失败报告；开发阶段加入字面缺数量消耗的确定性澄清后，开发集90/90，v1保留集60/60。

随后独立单元测试发现：引用任务补充字段未经过同样的注入检查，以及内外截止同时触发会丢失刚填写的字段。修正防注入并在工具读取前保留经过校验的新上下文，归档完整v1样本和结果。最终v2仍为150条，加入这两类场景，换用此前未用的51～70组作为独立保留集；没有根据保留集失败调整代码或样本。

最终冻结代码的真实模型开发90/90、保留60/60，意图、澄清和草稿字段检查均100%；开发P95 2.681秒、保留P95 2.778秒。规则开发90/90、保留60/60。当前逐条结果与服务器/本地哈希一致，见 delivery-and-validation.md 及 implementation-status.json。

真实模型使用本地 SSH 评测传输，仅发送合成文本到服务器已同步的 conversation.engines，私有密钥留服务器；不上传测试或评测文件。原本地 P0 共用账本继续累计，服务器账本也记录同一批调用，两个账本不得相加重复统计。无自动付费重试。代码版本以逐份报告的 runtime_hashes 核验。

## 联合验收清单：待前后端执行

| 场景 | 应有行为 |
|---|---|
| 移动牛奶，多批次 | 展示真实候选，不默认第一批 |
| 回复第二个 | 按当前修订候选解析，同一任务续接 |
| 草稿核对 | 显示旧位置/新位置、数量不变、待确认版本 |
| 确认整批移动 | 正式业务接口成功后才显示已执行，刷新库存 |
| 澄清时关闭窗口 | 原任务/修订/已填字段可恢复 |
| 消息响应丢失 | GET 原任务或原键原体恢复，无额外自动模型重试 |
| 确认响应丢失 | 保留稳定操作 ID，查询或同键恢复，不新建执行 |
| 多成员修改库存 | 版本冲突重新展示核对，不自动确认新版本 |
| 已执行但刷新失败 | 保留成功并提示待刷新，不重发确认 |
| 它在哪里 | 唯一/明确选择且引用有效时重读，歧义则询问 |
| 换物品/开始新任务 | 清除旧引用，新任务处理 |
| 家庭切换/注销 | 数据隔离，丢弃旧作用域异步回调 |
| 开封/丢弃缺接口 | 保留草稿、说明能力未就绪，不伪造操作成功 |
| 风险/预测缺数据 | 显示 unknown/不足/不可用和依据，不画虚假结果 |
| 补货入口 | 阈值补货和 AI 建议使用各自真实依据 |

验收目标：意图 ≥90%、澄清召回 ≥95%、草稿字段及专项边界全部正确，完整 AI 流程 P95 ≤10秒。夹具模型延迟不包含真实业务数据库、Android 渲染和正式确认事务，不能据此宣称产品 P95 达标。

最终本轮测试、评测及同步证据见 implementation-status.json；联合验收和正式发布保持未验证。
