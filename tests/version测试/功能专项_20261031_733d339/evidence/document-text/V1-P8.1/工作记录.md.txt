## 完成的 AI 修复

### 指定批次的只读查询

修复原来对非 P1 意图直接委派、丢失可信引用的问题。消费统计、耗尽预测、风险与补货建议均先检查引用身份与有效期，再读取当前批次。保留用户原文，不拼接猜测的名称。

前端当前四条固定查询文案均走确定性解析，零次模型调用：

| 页面原句 | 意图 |
| --- | --- |
| 查看它最近28天的消费统计 | QUERY_CONSUMPTION |
| 这批还能用多久？ | QUERY_FORECAST |
| 评估这批的风险和缺少的标签储存资料 | QUERY_RISK |
| 根据记录计算这批的补货建议，只展示建议，不提交采购 | SUGGEST_PURCHASE |

其他自然表达允许一次原有提取调用，并校验窗口天数及是否确实要求草稿；不会自动付费重试。原有“它在哪／它在什么地方／这批放在哪里”等确定性位置路径继续保留。

没有可信引用、引用对象删除或成为终态时要求重新明确对象。过期、跨家庭和库存版本不一致均拒绝沿用。后端只有商品组合历史、无法提供批次独立依据时，返回 `BATCH_PLANNING_SCOPE_UNAVAILABLE`，不会把商品合计冒充单批次统计。

### 全部用完与续接

“这批已经全部用完”等明确表达由确定性代码读取当前余量、单位和版本，生成消费草稿，标注 `quantity_source=current_batch`、`consume_mode=all`。缺对象时先补名称、再选批次，续接保留全部消费语义且不调用模型。

读取期间库存变化会要求重新核对；确认期间库存变化由既有预期版本校验拒绝。后端根据已保存的任务结果保护数量和单位，并要求草稿数量等于当前完整余量。修改为部分消费必须新建任务。消费成功只产生既有的一条 `Consumed` 事件，状态变为 `FINISHED`；幂等回放不重复执行。

### 包装单位与采购来源

在当前会话结果中增加 `inventory_unit`、`order_unit`、`pack_size`、`pack_size_source`，不修改旧 P3/P5/P6 的结果模型与历史 OpenAPI 快照。原 `unit` 保持表示建议采购量的单位。

可信引用的手动采购草稿增加独立 `procurement_source`，只含批次 ID 与预期版本。补数量或单位后仍保留来源，来源发生变化先重新核对。后端确认时检查家庭、活动状态、名称、版本和单位兼容性，将来源写入现有采购外键。没有明确来源的旧草稿或新物品仍不自动关联，不按同名推断。

### 降级与规则审核准备

缺已审核规则时增加 `HUMAN_RULE_REVIEW_REQUIRED`，将平台规则缺口与用户可补录事实分开；规则指导的 `fact_write_required=false`。用户补录库存资料不能替代规则审核。缺历史、完整覆盖日、待购、偏好、核对时间时保持准确降级，已读取事实继续保留。

新增本地规则候选与审核校验工具 `agent/review/rules.py`。候选全部禁用，保留现有来源与内容摘要；外部人工审核记录必须匹配规则 ID、版本和内容摘要，并通过日期、重复与审核方式检查。工具只能生成独立本地文件，不覆盖运行规则，不修改环境配置。它不鉴定审核人的真实身份，也不代替专业审核或重新核实外部来源。

本次没有录入真实人工批准记录，没有启用任何待审核规则。

## 后端小范围修补

均复用现有任务结果 JSON、库存、采购外键、DraftOperation 和 BusinessEvent：

| 项目 | 本地实现 |
| --- | --- |
| 全部消费保护 | 从已保存任务结果确定语义；禁止改数量／单位，校验完整余量和预期版本 |
| 手动采购来源 | 读取 AI 保存的来源并重新校验，写入现有 `source_inventory_item_id` |
| 家庭业务摘要 | 新增按家庭授权的脱敏摘要；不放开私人 task、draft 或原回执权限 |
| 归档读取 | 单批次详情 GET、显式状态筛选；默认列表仍为 ACTIVE/FINISHED |
| 执行后反馈 | 在正式成功回执之后独立调用现有只读 AI 反馈；释放 DB 连接后请求，无重试，10 秒总截止 |
| 采购反馈边界 | PLAN_ADD 明确只加入待购，无库存版本，不伪造库存反馈 |
| 兼容性诊断 | 按家庭分页定位不兼容批次及首个阻塞字段，不自动修改或忽略记录 |

未改数据库任务网关实现、锁顺序设计、数据库模型和迁移。未提供完整事件账本或撤销；摘要仅覆盖现有正式 AI 业务事件。
