# V1.5 现状分析与任务清单

分析日期：2026-10-25，Asia/Shanghai。本文依据当前工作区源码、原始总体规划及截至 2026-10-24 的阶段记录，明确当前基础、V1 遗留和 V1.5 待交付内容。

本文是版本评审与实施的任务草案，不表示 V1.5 已开发、已冻结排期或已获准接入外部模型。本次只核对文件，没有重新访问服务器、调用模型、运行测试或变更业务代码。历史测试与发布结果均按原记录引用。

## 1. 当前任务的判断

当前应在 V1-P8.1 的已交付基础上完成完整 V1 的产品收尾，同时准备 V1.5 的需求、契约与评测。不能仅凭服务上线或 AI 回归通过宣布完整 V1 验收完成。

V1.5 的产品目标是：**让已有库存助手能结合可追溯知识，判断哪些问题值得关注、何时提醒，以及为什么建议购买多少，并让用户完成查看、修改与确认。**

### 1.1 当前 App 的产品基础

当前 Mewstow 是 Kotlin / Jetpack Compose 原生 Android App，测试包标记为 `1.2.0-test`。主导航已固定为首页、库存、清单、我的，支持中英文和浅深色；这些界面基础应继续复用。

| 用户入口 | 已有用户能力 |
|---|---|
| 首页与助手 | 库存关注提示、文字问答、系统语音转文字、澄清与待确认草稿；登录后走远程 Agent，游客使用本地规则问答 |
| 库存与批次详情 | 搜索筛选、位置、资料与盘点、消耗/开封/移动/丢弃等操作入口、消费记录、风险/统计/预测结果展示 |
| 采购清单 | 手动添加、调整与移除、共享待购、按实际数量购买入库、已购历史；计算型建议的正式采纳事务仍受后端能力限制 |
| 我的与家庭 | 登录注册、游客入口、家庭创建/加入/切换、成员与角色、语言/主题/提醒设置，以及本机数据导出、帮助等配套入口 |

数据链路分为本机游客与登录后的家庭云端两种模式。游客数据独立保存在设备；云端由 App 经认证后端读取家庭库存、采购和业务回执，后端对接 Agent。业务写入仍走后端确认事务，模型输出不是执行回执。已有缓存隔离、版本冲突和重复购买保护，需继续做新旧链路的联合验收。

当前提醒开关和提醒天数主要是设备设置，物品最低阈值可同步服务器；照片仅在本机保存。不能把已有拍照入口、页面内提醒或四栏导航等同于图像识别、服务端主动通知或 V1.5 功能已接入。

## 2. V1.5 的范围

原始《CS353_AI_Agent系统总体规划》第 3.2 节与第 6 节给出了四条主线和一个可选项：

1. 联网搜索、RAG、候选规则校验，并保存来源和适用条件。
2. 新增 Risk Priority Score、Reminder Decision、Purchase Decision、Knowledge Relevance Judge 四类决策。
3. 临期、低库存、信息异常进入今日摘要或单条提醒，并限制打扰。
4. 采购建议结合风险库存、规格与用户明确偏好，数量和依据可追溯、可修改。
5. 图片/扫码辅助录入保持可选，结果继续进入既有草稿与确认链路。

V2 的通用主动监控 Agent、分层长期记忆、个性化预测、What-if 和反馈学习不纳入本次主范围。V1.5 可采用业务事件触发、打开 App 时补检查，以及支撑每日摘要所需的简单定时任务；不因此扩展成持续自主巡检系统。服务端任务与后续 V2 调度应留有兼容边界。

### 3.1 四类决策分别负责什么

| 决策 | 输入与输出 | 约束 |
|---|---|---|
| Risk Priority Score | 已计算风险、时间紧迫性、信息完整性等 → 关注顺序及原因 | 排序不能改变风险事实，也不能把 unknown 解释为可放心使用 |
| Reminder Decision | 风险/库存事实、历史提醒、用户偏好 → 即时、摘要、延后或抑制 | 去重、频率、免打扰由代码强制执行；模型不能突破用户设置 |
| Purchase Decision | 库存/风险/待购/偏好完整性、确定性计算结果 → 建议采购、暂缓或补资料 | 不负责算数量，不执行采购、不自动下单 |
| Knowledge Relevance Judge | 当前问题、物品条件、检索证据 → 相关、无关或不确定及依据 | 相关不等于规则已审核，不等于能覆盖包装标签 |

原规划要求的是这四类新增 Jev 节点，P9 现有四节点不能抵数。应先复用 P9 的调用、响应校验、预算、追踪和回放能力完成新任务评测，再决定接入方案。现有实验仅允许合成场景；真实业务数据适配、正式调用与部署仍属于 V1.5 的条件交付，效果达标并满足既有业务接入约定后实施。条件未满足时应保留待完成状态，或评审调整版本范围，不能只凭独立实验模块就宣布产品接入完成。

运行时保留规则回退保证基础功能可用。若 Jev 的中文效果、延迟或成本收益不达标，应明确调整范围或继续实验，不能把规则结果标成 Jev 已完成验收。

### 3.2 知识与规则的两条输出

知识问答可以返回带来源的参考材料；进入风险引擎的规则必须经过适用性检查和真实人工审核。两者不共享一个“检索到即可信”的开关。

建议链路为：受控知识源 → 文档与来源版本 → 检索证据 → 带引用解释 / 禁用的候选规则 → 人工审核发布 → 风险工具使用。现有本地 RuleCatalog 和候选审核工具应复用，不需要为最小交付强行新建完整审核后台。

联网检索失败时可使用仍有效的已有审核规则或说明知识暂不可用；不得伪造来源、自动放行未审规则，也不改变用户登记事实。

### 3.3 基础提醒的最小闭环

真实变化或摘要时点 → 读取当前家庭事实 → 规则计算 → 决策与频控 → 保存提醒/摘要 → App 查看 → 进入业务页或记录处置反馈。

临期可直接依据真实标签日期；低库存可依据已核对数量和用户阈值；规则未知或资料不足应产生信息异常提示，不能凭空推断可用性。无需让每条基础提醒都依赖一次联网或模型调用。

去重应按家庭、对象、原因和状态阶段识别同一问题，不能把每次任务重试或无关版本变化都当成新提醒。延后、状态恶化、库存终态、规则停用及已处理后的再次触发，应有明确的重评规则。

原规划允许今日摘要或单条提醒。建议最小交付采用持久化应用内提醒和摘要，具体入口组合由 V15-00 冻结；系统级推送是否列为必做、采用什么通道，同样需要评审冻结。现有页面内提示不能直接当作后台推送已实现。

### 3.4 采购增强的增量

V1 已有目标缺口、待购抵扣、风险拦截和包装取整。V1.5 的工作是让这些依据在真实商品/批次上完整可用，并增强风险处理、明确偏好、说明与反馈。

风险不明或橙/红风险时，当前算法会停止确定性建议。应明确后续哪些情况继续要求核对，哪些情况允许在已验证可用库存上计算；不能把未知库存直接当成零以制造采购量。跨包装换算只使用有来源的规格，不按容器名称猜容量。

现有药品采购明确排除，V1.5 不默认扩大该范围。价格优化、品牌推荐、电商下单、自动学习偏好也不属于本次已确定主范围。

## 6. 建议冻结的验收条件

| 验收面 | 必须证明的结果 |
|---|---|
| 知识 | 每条知识解释可找到实际支持它的来源与版本；无来源、冲突、过期与不适用场景正确降级；标签事实不被覆盖 |
| 规则 | 未审核候选不进入运行；审核记录对应实际内容版本；规则可停用/回退，更新后的旧结果能识别失效 |
| 四类决策 | 人工复核数据、开发/校准/保留集分离；报告每任务效果、错误类型、调用失败、端到端延迟与实际费用；不能只报告连通成功 |
| 提醒 | 规则触发、去重、配额、免打扰、延后与已处理状态可重复验证；重复任务不重复提醒；用真实试用记录评估是否过度打扰，并记录理解度与忽略/延后原因 |
| 采购 | 6 盒/包等包装案例数量与单位正确；待购被抵扣；未知数据拒绝伪精确；建议可修改且来源保留；并发修改需重新核对 |
| 业务与权限 | 确认前无库存副作用；重复确认仅执行一次；反馈不更改库存；跨家庭读写拒绝，切换家庭与终态对象处理正确 |
| App 与恢复 | 提醒/知识/建议均有真实入口和状态；网络、模型、来源失败及写入结果不明可恢复；反馈超时不重放成功业务 |
| 兼容性 | 既有 V1 工具请求、结果和用户流程继续可用；新增知识、决策及可选图片入口不破坏草稿、澄清、确认、权限与幂等契约 |

上线前需冻结：知识首批覆盖范围与检索质量目标、四类决策的分项指标、提醒频率/冷却与试用评价方式、全链路 P95/失败率/成本预算、真实采购效果的样本和判断标准。当前规划未给出这些数值，本文不将建议包装成已达成的门槛。

建议形成三条产品演示并保存真实链路证据：

- **知识解释：** 选择真实批次 → 询问储存/开封相关问题 → 展示适用证据与缺项 → 补充真实标签后重新评估。
- **基础提醒：** 受控触发临期/低库存/信息异常 → 摘要或提醒 → 验证去重与免打扰 → 打开对象 → 记录延后/处理。
- **采购建议：** 同商品多批次、已有待购、真实包装规格 → 展示建议和依据 → 修改最终量 → 确认时复核 → 仅加入待购，库存保持不变。
